## Énoncé et corrigé fourni


You have an Azure web app named App1 that uses deployment slots, as shown below:
- webapp1-prod -> Production
- webapp1-test -> Staging
You validate multiple updates to App1 in the webapp1-test slot.
After completing testing, you create a backup of App1.
You then swap the webapp1-test slot with webapp1-prod, after which the application starts showing performance problems.
You must roll back App1 to the earlier, stable version in the shortest possible time.
What action should you take?
Réponses:
☐ Restore App1 from the backup.
☐ Create a clone of App1.
☐ Redeploy the application to App1.
**☑** Swap the deployment slots again.
Explication
`Swap the deployment slots again` is the correct answer here. Azure App Service deployment slots allow you to deploy and test changes in a staging slot (in this case, `webapp1-test`) and then swap the staging slot with the production slot (`webapp1-prod`) when ready. When a swap is performed, the content and configuration of the slots are exchanged, allowing for a quick rollback if needed.
Since you already swapped the test slot into production and discovered performance issues, the fastest way to revert is to swap the slots again. This will return the original production version (which is now in the test slot) back to its place, restoring the last working state almost instantly and with zero downtime.
`Restore App1 from the backup` is incorrect because although it can restore the app to a previous state, it is a slower operation and involves data loss risk and manual effort, making it less ideal for quick recovery.
`Create a clone of App1` is incorrect because cloning creates a new app instance, which is not a recovery mechanism and would not affect the current deployment state of App1.
`Redeploy the application to App1` is incorrect because this would require rebuilding and redeploying the application code, which takes more time and may not exactly match the last known good state.
Reference(s.):
- https://learn.microsoft.com/en-us/azure/app-service/deploy-staging-slots
