## Énoncé et corrigé fourni


You have an Azure subscription that includes the following resources:
- VMRG – Resource group
- VNet1 – Virtual network
- VNet2 – Virtual network
- VM5 – Virtual machine connected to VNet1
- VM6 – Virtual machine connected to VNet2
You create an Azure private DNS zone named apexcore.com.
You then link the private DNS zone to VNet2 and enable auto-registration for the virtual network link.
The apexcore.com private DNS zone is configured with existing DNS records, as shown in the below exhibit.
True or False:
`“VM5 can resolve VM9.apexcore.com."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct. VM5 cannot resolve VM9.apexcore.com because VM5 is connected to VNet1, while VM9 is connected to VNet2. Forward DNS resolution is only supported across virtual networks that are linked to the private DNS zone as resolution virtual networks. In this setup, VNet2 is linked to the apexcore.com private DNS zone, but VNet1 is not linked to this zone nor is it peered with VNet2. Since VNet1 is not configured as a resolution virtual network, VM5 cannot resolve the domain name VM9.apexcore.com.
Reference(s):
- https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns
- https://learn.microsoft.com/en-us/azure/dns/private-dns-overview
