## Énoncé et corrigé fourni


You have a Windows 11 computer named Device1 and an Azure subscription that includes the following resources:
- A virtual network named VNET1
- A virtual machine named VM1 that runs Windows Server 2022, has no public IP address, and is connected to VNET1
- An Azure Bastion Basic SKU host named Bastion1 that is connected to VNET1
Device1 has both Azure PowerShell and the Azure CLI installed.
You need to establish a Remote Desktop (RDP) connection from Device1 to VM1.
Which three actions should you perform in sequence?
ACTIONS
- From Bastion1, select Native Client Support.
- On Device1, run mstsc.exe.
- Upgrade Bastion1 to the Standard SKU.
- From Bastion1, enable Kerberos authentication.
- From VM1, enable just-in-time (JIT) VM access.
- From Azure CLI on Device1, run az network bastion rdp.
Réponses:
☐ 3-6-1
☐ 3-4-1
☐ 3-2-6
**☑** 3-1-6
Explication
`(Action 3) Upgrade Bastion1 to the Standard SKU` – To use the native client feature for Azure Bastion, which allows connecting via a local RDP client (such as mstsc.exe), Bastion1 must be upgraded to the Standard SKU, as this feature is not available with the Basic SKU.
`(Action 1) From Bastion1, select Native Client Support` – After upgrading, enable the native client support option within the Azure Bastion configuration. This feature allows Device1 to connect to VM1 through Bastion using an RDP client.
`(Action 6) From Azure CLI on Device1, run az network bastion rdp` – Use the `az network bastion rdp` command on Device1’s Azure CLI to initiate the RDP connection to VM1 through Bastion1. This command establishes the RDP session without requiring the direct use of `mstsc.exe`.
To connect via RDP, use the following command:
`az network bastion rdp --name "<BastionName>" --resource-group "<ResourceGroupName>" --target-resource-id "<VMResourceId>"`
`(Action 2) On Device1, run mstsc.exe` is not necessary when using the Azure CLI command, as `az network bastion rdp` initiates the connection directly.
`(Action 4) Enable Kerberos authentication` and `(Action 5) Enable just-in-time (JIT) VM access` are not required for this setup.
