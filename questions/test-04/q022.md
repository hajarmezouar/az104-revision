## Énoncé et corrigé fourni


You have an on-premises server that contains a folder named at D:\DataFolder.
You need to upload all the contents of D:\DataFolder to the public blob container in an Azure Storage account named apexcoredata.
Which command should you run to complete this task?
Réponses:
☐ az storage blob copy start D:\DataFolder https://apexcoredata.blob.core.windows.net/public
**☑** azcopy copy D:\DataFolder https://apexcoredata.blob.core.windows.net/public --recursive
☐ azcopy sync D:\DataFolder https://apexcoredata.blob.core.windows.net/public --snapshot
☐ az storage blob copy start-batch D:\DataFolder https://apexcoredata.blob.core.windows.net/public
Explication
`azcopy copy D:\DataFolder https://apexcoredata.blob.core.windows.net/public --recursive` is the correct answer because the `azcopy copy` command is used to upload files from an on-premises folder to an Azure Storage container. The `--recursive` option ensures that all files within D:\Folder1 are copied to the destination container in Azure.
`az storage blob copy start D:\DataFolder https://apexcoredata.blob.core.windows.net/public` is incorrect because `az storage blob copy start` is intended for copying blobs within Azure Storage, not for uploading files from an on-premises location.
`azcopy sync D:\DataFolder https://apexcoredata.blob.core.windows.net/public --snapshot` is incorrect because `azcopy sync` is used to synchronize files between a local folder and a storage container, rather than a direct copy. The `--snapshot` parameter is not relevant for this task.
`az storage blob copy start-batch D:\DataFolder https://apexcoredata.blob.core.windows.net/public` is incorrect because `az storage blob copy start-batch` is designed for batch copying blobs within Azure Storage, not from an on-premises location.
