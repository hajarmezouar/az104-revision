## Énoncé et corrigé fourni


You manage an Azure subscription that contains an existing Azure Storage account.
You plan to deploy an Azure Container Instance named sqlcontainer01, which runs a Docker image named mssqlimage01. The image includes a Microsoft SQL Server instance that requires persistent data storage beyond the lifecycle of the container.
You must configure a storage solution that ensures the SQL Server data remains available even if sqlcontainer01 is restarted or redeployed.
Which Azure storage service should you use to provide persistent storage for sqlcontainer01?
Réponses:
☐ Azure Queue storage
☐ Azure Blob storage
☐ Azure Table storage
**☑** Azure Files
Explication
`Azure Files` is the correct answer because it provides a fully managed SMB file share that can be mounted by Azure container instances as persistent storage. This is essential for scenarios like running Microsoft SQL Server in a container, where data needs to persist across container restarts. However, it is important to note that volume mounting, including Azure Files, is currently only supported for `Linux-based` Azure container instances. Therefore, this solution assumes that mssqlimage01 is a Linux container image running SQL Server for Linux (which is fully supported).
`Azure Queue storage` is incorrect because it is designed for messaging between application components and does not provide file system-based persistent storage.
`Azure Blob storage` is incorrect because it is used for storing unstructured object data and cannot be mounted as a file system by container instances.
`Azure Table storage` is incorrect because it is a NoSQL key-value store intended for structured data and not suitable for use as a mounted persistent file system.
Reference(s):
- https://learn.microsoft.com/en-us/azure/container-instances/container-instances-volume-azure-files
- https://learn.microsoft.com/en-us/azure/storage/files/storage-files-introduction
