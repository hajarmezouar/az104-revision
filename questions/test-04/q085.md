## Énoncé et corrigé fourni


You have deployed Azure virtual machines across three different Azure regions.
In each region:
- There is one virtual network.
- Each virtual network contains multiple subnets.
- All virtual networks are connected using full-mesh VNet peering.
A user reports that they are unable to connect over TCP port 33000 from a virtual machine in one region to a virtual machine in another region.
Which two options can you use to investigate and troubleshoot this connectivity issue?
Réponses (plusieurs réponses possibles)
☐ Azure Monitor Network Insights
**☑** IP flow verify
☐ effective security rules
☐ Azure Virtual Network Manager
**☑** Connection troubleshoot
Explication
`IP flow verify` is correct because it allows you to test whether traffic is allowed to or from a virtual machine based on NSG (Network Security Group) rules. It specifically helps in identifying whether a particular port (like 33000) is blocked or allowed, which is essential for troubleshooting connectivity between VMs.
`Connection troubleshoot` is correct because it helps diagnose issues with connectivity between two endpoints. It checks DNS resolution, network latency, and whether TCP connections (like on port 33000) can be established, making it ideal for this scenario involving cross-region VM communication.
`Azure Monitor Network Insights` is incorrect because it gives you a high-level view of the health and topology of your network resources, but it doesn't perform port-level diagnostics or simulate connection attempts.
`effective security rules` is incorrect because it shows the final set of NSG rules applied to a NIC or subnet but doesn't actively test whether a specific port is blocked or allowed. It's useful for analysis, but not direct diagnostics.
`Azure Virtual Network Manager` is incorrect because it's used for centralized network management and policy enforcement across VNets, not for diagnosing connectivity issues like blocked ports.
