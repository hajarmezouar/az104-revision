## Énoncé et corrigé fourni


You manage two Azure subscriptions: Subscription1 and Subscription2.
In Subscription1, the following resource groups exist:
- RG1 – Region: West Europe – Lock: None
- RG2 – Region: West Europe – Lock: Read-only
The resource group RG1 contains a web application named App1, which is deployed in the West Europe region.
In Subscription2, the following resource groups are configured:
- RG3 – Region: North Europe – Lock: Delete
- RG4 – Region: Central US – Lock: None
True or False:
`“App1 can be moved to RG3.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer because Azure allows moving supported resources, such as an App Service web app, between resource groups and even between subscriptions within the same tenant. When a resource is moved between resource groups or subscriptions, the resource itself does not move to another region. Only the Azure Resource Manager metadata changes, and the resource continues to run in its original region.
In this scenario, App1 is deployed in the West Europe region, and moving it to RG3 does not change its location. Even though RG3 is associated with North Europe, resource groups can contain resources from different regions, so this does not prevent the move.
Additionally, if the web app depends on other resources, such as an App Service Plan, those dependent resources must be moved together in the same operation.
The Delete lock on RG3 does not block the move because a delete lock only prevents deletion of the resource group or its resources. It does not prevent adding or moving resources into the resource group.
Therefore, App1 can be moved to RG3, making the statement True.

- https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-support-resources
- https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/lock-resources
