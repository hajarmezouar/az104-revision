## Énoncé et corrigé fourni


You have an Azure subscription that includes a virtual machine named VM1, which hosts a line-of-business application that must remain available around the clock. VM1 has a single network interface, one managed disk, and is currently configured with the D4s v3 size.
You plan to apply the following modifications to VM1:
- Resize the virtual machine to D8s v3.
- Attach an additional 500-GB managed disk.
- Install the Puppet Agent virtual machine extension.
- Enable Desired State Configuration (DSC) management.
Which of these changes will result in downtime for VM1?
Réponses:
☐ Adding the Puppet Agent extension.
☐ Attaching a 500-GB managed disk.
**☑** Changing the size to D8s v3.
☐ Enabling Desired State Configuration Management.
Explication
`Changing the size to D8s v3` is the correct answer here. Changing the size of a virtual machine in Azure requires it to be deallocated and then re-provisioned, which causes downtime. During the resizing process, VM1 will not be available, resulting in a temporary outage for the line-of-business application.
`Adding the Puppet Agent extension` is incorrect because adding an extension to a virtual machine does not require deallocation, so it does not cause downtime.
`Attaching a 500-GB managed disk` is incorrect because attaching an additional managed disk to a virtual machine can be done while the VM is running, and it does not cause downtime.
`Enabling Desired State Configuration Management` is incorrect because enabling Desired State Configuration (DSC) does not require the virtual machine to be stopped or deallocated, so it does not cause downtime.

- https://azure.microsoft.com/en-us/blog/resize-virtual-machines
