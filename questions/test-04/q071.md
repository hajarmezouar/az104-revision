## Énoncé et corrigé fourni


You have an Azure subscription named Sub1 with the subscription ID 8f3a1c92-5d47-4b6e-a2f9-71c3d8e5ab40.
You want to create a custom Azure RBAC role named CustomRole1 that meets the following conditions:
- The role can be assigned only at the resource group scope within Sub1.
- The role must not allow users to manage access permissions (RBAC) on the resource groups.
- The role must allow users to view, create, update, and delete resources inside the resource groups.
You are defining the role by using a JSON definition that includes the assignableScopes and permissions sections.
What value should you specify for `Code Segment A` in the definition of CustomRole1?

Explication
`"/subscriptions/8f3a1c92-5d47-4b6e-a2f9-71c3d8e5ab40"` is the correct answer here. The assignableScopes property defines where a custom role can be assigned, and it accepts scopes such as management groups, subscriptions, or specific resource groups. Since Subscription1 has a subscription ID of 8f3a1c92-5d47-4b6e-a2f9-71c3d8e5ab40, and the requirement is to allow assignment of the role only to resource groups within this subscription, the correct assignable scope is the subscription level. This ensures the custom role is available for assignment at the resource group level within that subscription without being overly permissive.
`"/"` is incorrect because the root scope is not supported in custom role definitions. AssignableScopes cannot be set to "/", and attempting to do so will result in a validation error.
`"/subscriptions/8f3a1c92-5d47-4b6e-a2f9-71c3d8e5ab40/resourceGroups"` is incorrect because this is not a valid scope. The string "resourceGroups" is a collection placeholder, and not a valid scope by itself. Using it will result in a validation error such as:
"Validation error: Invalid scope: /subscriptions/<SubscriptionID>/resourceGroups".
Additionally, the question does not reference any specific resource group. It refers broadly to “resource groups” within the subscription, and therefore the assignable scope must be set at the subscription level.
