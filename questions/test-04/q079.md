## Énoncé et corrigé fourni


You have the following Azure virtual networks configured:
- VNet1
- Address space: 10.11.0.0/16
- Subnet: 10.11.0.0/17
- Resource group Azure region: West US
- VNet2
- Address space: 10.11.0.0/17
- Subnet: 10.11.0.0/25
- Resource group Azure region: West US
- VNet3
- Address space: 10.10.0.0/22
- Subnet: 10.10.1.0/24
- Resource group Azure region: East US
- VNet4
- Address space: 192.168.16.0/22
- Subnet: 192.168.16.0/24
- Resource group Azure region: North Europe
You want to configure virtual network peering for VNet1.
Which of the listed virtual networks can be peered with VNet1?
Réponses:
☐ VNet2 only
**☑** VNet3 and VNet4 only
☐ VNet2 and VNet3 only
☐ VNet2, VNet3, and VNet4
Explication
`VNet3 and VNet4 only` is the correct answer here. To peer virtual networks in Azure, one of the main requirements is that the address spaces must not overlap. In the case of VNet1 (10.11.0.0/16):
- VNet2 (10.11.0.0/17) has an address space that overlaps with VNet1. Peering is not allowed in this case due to the overlapping IP ranges, even though it’s in the same region.
- VNet3 (10.10.0.0/22) has a non-overlapping address space and is in a different region (East US), which is still supported via global virtual network peering.
- VNet4 (192.168.16.0/22) also has a non-overlapping address space and is in North Europe, which again supports global VNet peering.
Therefore, only VNet3 and VNet4 can be peered with VNet1.
