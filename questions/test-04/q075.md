## Énoncé et corrigé fourni


You have a pay-as-you-go Azure subscription with the following virtual machines:
- VM1 in resource group RG1, costing 20 euros per day
- VM2 in resource group RG2, costing **30 euros per day
You create the budget shown in the following exhibit.
The budget is set up with alert thresholds at 50%, 70%, and 100%, each linked to different action groups.
The action group AG1 contains only the user admin@apexcore.com.
Based on this configuration, complete the following statement:
“Given the existing usage costs of the virtual machines, _________________________.”
Réponses:
☐ no email notifications will be sent each month
**☑** one email notification will be sent each month
☐ two email notifications will be sent each month
☐ three email notifications will be sent each month
Explication
`one email notification will be sent each month` is the correct answer here. This is a common area of confusion, so let's clarify it step by step to avoid misinterpretation.
In the provided scenario:
- VM1 is the only virtual machine within the scope of Budget1 (since VM1 is in RG1, and the budget is scoped to RG1).
- VM1 costs €20 per day, which totals approximately €600 per month.
- The budget thresholds are:
- 50% of €1,000 → triggers Action Group AG1 (configured to send 1 email)
- 70% of €1,000 → triggers AG2 (sends 1 SMS)
- 100% of €1,000 → triggers AG3 (sends 1 Azure app notification)
At €600, only the 50% threshold is crossed, which triggers AG1.
Why it’s not two emails:
You may mistakenly think that:
- One email is sent because AG1 is triggered
- Another email is sent because admin@apexcore.com is listed as an alert recipient
This is not correct.
In Azure Budgets, email alerts are sent only via Action Groups. The person listed (e.g., `admin@apexcore.com`) in the budget configuration is part of the Action Group (AG1) that is associated with the 50% threshold. They are not receiving a second, separate notification outside the Action Group.
So even though the name appears in the recipient list, it does not represent an additional notification beyond what AG1 is configured to send.
