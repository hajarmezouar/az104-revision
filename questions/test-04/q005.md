## Énoncé et corrigé fourni


You have an Azure subscription that includes the following public IP address resources:
- IP1: IPv4, Standard SKU, Regional tier, Static assignment
- IP2: IPv4, Standard SKU, Global tier, Static assignment
- IP3: IPv4, Basic SKU, Regional tier, Dynamic assignment
- IP4: IPv4, Basic SKU, Regional tier, Static assignment
- IP5: IPv6, Basic SKU, Regional tier, Dynamic assignment
You plan to deploy an Azure Bastion host named Bastion1 using the Basic SKU.
Which of the listed public IP addresses can be used for Bastion1?
Réponses:
**☑** IP1 only
☐ IP1 and IP2 only
☐ IP3, IP4, and IP5 only
☐ IP1, IP2, IP4, and IP5 only
☐ IP1, IP2, IP3, IP4, and IP5
Explication
`IP1 only` is the correct answer because Azure Bastion requires a Standard Public IP address for both the Basic and Standard SKUs. Additionally, the IP address must be IPv4, have a Regional tier, and use a Static assignment. Among the provided options, IP1 is the only address that satisfies all these conditions, making it suitable for Azure Bastion.
Note: The Microsoft documentation does not explicitly list “Regional tier” as a Bastion requirement. However, in practice, Azure Bastion supports only Regional tier public IPs. Global tier public IPs are intended for cross-region load balancers and cannot be attached to Azure Bastion. This behavior is also confirmed when attempting deployment in the Azure portal, where attaching a Global tier public IP to Bastion results in an error.
- IP2 is incorrect because it has a Global tier, while the requirement is for a Regional tier.
- IP3 is incorrect due to its Basic SKU and Dynamic assignment, both of which are incompatible with Azure Bastion.
- IP4 is incorrect because it also uses the Basic SKU, which does not meet the Standard SKU requirement.
- IP5 is incorrect as it is an IPv6 address, and Azure Bastion supports only IPv4.
