## Énoncé et corrigé fourni


You have an Azure subscription that includes the resources mentioned below:
- A virtual network named VNet1
- A subnet named Subnet1, which is part of VNet1
- Two virtual machines, VM1 and VM2, both deployed to Subnet1
VM1 and VM2 were created from the same deployment template and host line-of-business applications.
You configure a network security group (NSG) as shown in the exhibit.
You need to ensure that users on VM1 and VM2 are unable to browse websites on the internet by using TCP port 80.
What should you do?
Réponses:
☐ Modify the DenyWebSites outbound security rule.
☐ Update the Port_80 inbound security rule.
**☑** Associate the network security group with Subnet1.
☐ Remove the network security group association from a network interface.
Explication
`Associate the network security group with Subnet1` is the correct answer here. The question specifies the need to prevent users of VM1 and VM2 from accessing websites on the Internet over TCP port 80. In the exhibit, there is an outbound rule, DenyWebSites, configured to block traffic on TCP port 80. However, if you look at the "Associated with" section in the top right corner of the exhibit, it shows "0 subnets, 0 network interfaces", meaning this NSG is not currently associated with any subnet or network interface.
To apply this restriction to VM1 and VM2, which are located in Subnet1, it is necessary to associate the NSG with Subnet1. By doing so, the NSG rules, including the DenyWebSites rule, will take effect, blocking outbound access to websites on TCP port 80 for both VM1 and VM2. Therefore, Associate the NSG to Subnet1 is the correct choice here.
`Modify the DenyWebSites outbound security rule` is incorrect because modifying the rule itself won’t make any difference if the NSG is not associated with Subnet1 or the network interfaces of VM1 and VM2.
`Update the Port_80 inbound security rule` is incorrect because this rule manages inbound traffic on port 80, which is unrelated to the requirement to restrict outbound web access.
`Remove the network security group association from a network interface` is incorrect because there is no existing association to remove, as indicated by the "0 subnets, 0 network interfaces" status.
