## Énoncé et corrigé fourni


You have an Azure subscription that includes a virtual machine named VM1.
VM1 hosts a financial reporting application (App1) that is designed to run as a single active instance only.
At the end of every month, App1 performs intensive processing, which causes CPU utilization on VM1 to spike significantly.
You are required to create an Azure Automation scheduled runbook that temporarily improves the CPU performance of VM1 during this monthly processing window.
Which action should the runbook perform?
Réponses:
☐ Move VM1 into a virtual machine scale set so that compute capacity can scale automatically.
☐ Install the Azure Performance Diagnostics extension on VM1 to analyze CPU bottlenecks.
**☑** Change the virtual machine size of VM1 to a SKU that provides more vCPUs and processing power.
☐ Request an increase to the subscription’s vCPU quota to allow additional processors.
☐ Apply a Desired State Configuration (DSC) extension to VM1 to optimize system settings.
Explication
`Change the virtual machine size of VM1 to a SKU that provides more vCPUs and processing power` is correct as we need to add more processing power to the machine, which can be achieved by increasing the size of the VM. This approach allows scaling vertically by assigning more vCPUs or memory resources, ensuring the virtual machine can handle the increased CPU demand at the end of each month when the financial reporting application runs.
`Install the Azure Performance Diagnostics extension on VM1 to analyze CPU bottlenecks` is incorrect as this agent is primarily used for collecting diagnostic logs and performance data from the virtual machine into Azure Monitor. It does not enhance the processing power of the VM, which is the core requirement in this scenario.
`Move VM1 into a virtual machine scale set so that compute capacity can scale automatically` is incorrect because a scale set runs identical instances of a VM to handle increased load horizontally. However, the financial reporting application running on VM1 does not support multiple active instances, rendering this option unsuitable.
`Request an increase to the subscription’s vCPU quota to allow additional processors` is incorrect because increasing the vCPU quota is only necessary when the subscription has exhausted its vCPU limit. In this scenario, we only need to increase the resources of a single virtual machine, not the overall quota for the subscription.
`Apply a Desired State Configuration (DSC) extension to VM1 to optimize system settings` is incorrect as DSC is used to enforce consistent configurations across multiple virtual machines. This approach does not address the requirement to increase the processing power of a single VM for a specific period.
