## Énoncé et corrigé fourni


You have an Azure subscription that contains the following resource groups:
- RG1: Region: East US
- RG2: Region: West US
You create the following Azure Resource Manager (ARM) template named deploy.json.
{
"$schema": "https://schema.management.azure.com/schemas/2015-01-01/deploymentTemplate.json#",
"contentVersion": "1.0.0.0",
"parameters": {},
"variables": {},
"resources": [
{
"type": "Microsoft.Resources/resourceGroups",
"apiVersion": "2018-05-01",
"location": "eastus",
"name": "[concat('RG', copyIndex())]",
"copy": {
"name": "copy",
"count": 4
}
}
],
"outputs": {}
}
You deploy the template by running the following cmdlet:
`New-AzSubscriptionDeployment -Location westus -TemplateFile deploy.json`
True or False:
`“The template creates a resource group named RG3 in the West US Azure region.”`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer here. The ARM template defines the creation of resource groups using the `Microsoft.Resources/resourceGroups` type and specifies the `"location": "eastus"` inside the resource definition. This means all resource groups created by the template, including RG3, are created in the East US region.
While the deployment is executed using the command:
New-AzSubscriptionDeployment -Location westus -TemplateFile deploy.json
the `-Location westus` argument only defines the deployment metadata region, not the region of the resources being deployed. The actual resource group location is explicitly defined in the template as `"eastus"`.
Reference(s.):
- https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-to-subscription
