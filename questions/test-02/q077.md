## Énoncé et corrigé fourni


You are planning to deploy a new Azure App Service application named WebApp1. The configuration must satisfy the following conditions:
- WebApp1 must support validating a custom domain name: app.bluerock.com.
- WebApp1 must be able to automatically scale up to a maximum of eight instances.
- The selected solution should keep costs low and reduce ongoing administrative overhead as much as possible.
Based on these requirements, which App Service pricing plan should you select for WebApp1?
Réponses:
☐ Basic
☐ Free
☐ Shared
**☑** Standard
Explication
`Standard` is correct. The Standard App Service plan supports both custom domain name verification and auto-scaling, which are required for WebApp1. It allows binding of a custom domain such as `app.bluerock.com` and supports automatic scaling up to 10 instances, which satisfies the requirement to scale up to eight instances. Additionally, it offers a balance between cost and functionality, minimizing administrative effort while supporting enterprise-grade features.
`Basic` is incorrect because although it supports custom domains, it does not support auto-scaling. The scaling process under the Basic tier is manual, which does not meet the requirement for automatic scaling.
`Free` is incorrect because it does not support custom domain binding or scaling beyond a single instance. It is intended for development or testing scenarios with limited capabilities.
`Shared` is incorrect because it also lacks support for custom domains and does not offer scalability. Like the Free tier, it is meant for lightweight, shared environments with constrained features.
