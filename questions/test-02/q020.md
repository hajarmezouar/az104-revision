## Énoncé et corrigé fourni


Note: This question is part of a series that uses the same overall scenario. Each question in the series proposes a different solution that may or may not satisfy the stated requirement.
An application named App1 is deployed on two Azure virtual machines, VM1 and VM2. Incoming traffic to App1 is distributed by an Azure Load Balancer.
The effective network security rules applied to VM2 are shown in the exhibit.
You observe that client connections originating from the IP address 131.107.100.50 fail when attempting to reach App1 over TCP port 443. You verify that the Load Balancer configuration is correct.
Your objective is to ensure that connections from 131.107.100.50 to App1 over TCP port 443 are successfully established.
Proposed solution: You add a new inbound network security rule that explicitly blocks all incoming traffic originating from the IP address 131.107.100.50 and assign the rule a priority value of 64999.
Does this solution achieve the stated objective?
Réponses:
☐ Yes
**☑** No
Explication
`No` is correct because creating an inbound security rule that denies all traffic from 131.107.100.50 with a priority of 64999 will block connections from this IP, which is the opposite of the requirement. The goal is to allow connections to App1 from 131.107.100.50 on TCP port 443, not to deny them. Additionally, a deny rule would prevent any successful connection from this IP, making it impossible to establish the required connectivity to App1.
