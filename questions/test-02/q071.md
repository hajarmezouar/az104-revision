## Énoncé et corrigé fourni


You have an Azure subscription that contains the following resource groups:
- RG1: Region: East US
- RG2: Region: West US
You create the following Azure Resource Manager (ARM) template named deploy.json.
{
"$schema": "https://schema.management.azure.com/schemas/2015-01-01/deploymentTemplate.json#",
"contentVersion": "1.0.0.0",
"parameters": {},
"variables": {},
"resources": [
{
"type": "Microsoft.Resources/resourceGroups",
"apiVersion": "2018-05-01",
"location": "eastus",
"name": "[concat('RG', copyIndex())]",
"copy": {
"name": "copy",
"count": 4
}
}
],
"outputs": {}
}
You deploy the template by running the following cmdlet:
`New-AzSubscriptionDeployment -Location westus -TemplateFile deploy.json`
True or False:
`“The template creates four new resource groups.”`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer here. While the ARM template is intended to create four resource groups (RG0, RG1, RG2, RG3), the table provided in the question shows that RG1 and RG2 already exist in the subscription. Azure Resource Manager (ARM) templates do not overwrite existing resource groups — attempting to create a resource group with a name that already exists will cause that specific deployment iteration to fail, unless the template logic explicitly handles existing resources (which this one does not).
As a result:
- RG0 and RG3 will be created
- RG1 and RG2 will fail to deploy because they already exist.
Reference(s.):**
- https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-to-subscription
