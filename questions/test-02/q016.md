## Énoncé et corrigé fourni


You are designing an Azure Storage solution and must provision a storage account that satisfies the following design constraints:
- Blob data must be able to use all access tiers, including hot, cool, and archive
- The solution must remain resilient if the primary Azure region becomes unavailable
- The configuration should be as cost-effective as possible
You plan to deploy the storage account by using the Azure CLI command shown below:
How should you complete the following command?
`az storage account create -g RG1 -n storageaccount1 --kind ____ --sku ____`
Réponses:
☐ --kind FileStorage --sku Standard_GRS
☐ --kind Storage --sku Standard_LRS
☐ --kind StorageV2 --sku Standard_RAGRS
**☑** --kind StorageV2 --sku Standard_GRS
☐ --kind FileStorge --sku Premium_LRS
Explication
`--kind StorageV2 --sku Standard_GRS` is correct because StorageV2 is the only account kind that supports all three blob storage tiers—Hot, Cool, and Archive. Additionally, the Standard_GRS SKU provides geo-redundancy, which replicates data to a secondary region to ensure resiliency against regional failures, aligning with the requirement for regional fault tolerance.
