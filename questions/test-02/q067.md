## Énoncé et corrigé fourni


You are working in an Azure subscription and plan to deploy a storage account named storage1 by using an Azure Resource Manager (ARM) template.
The template configuration enables several data protection features for the Blob service, including blob versioning, soft delete, container soft delete, and point-in-time restore with specific retention periods.

"resources": [

True or False:
`"Only users who are geographically located in the East US Azure region are permitted to access storage1."`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer because there is nothing in the ARM template that restricts network access to the East US region. The `"location": "East US"` property only specifies where the storage account is deployed — it does not limit who can access it. The `networkAcls` configuration explicitly allows all traffic with `"defaultAction": "Allow"` and contains no IP rules or virtual network restrictions. This means users from any region can connect to `storage1` as long as they have valid credentials.
The allowBlobPublicAccess property in the template controls anonymous blob access, not regional access. Since no firewall, IP restrictions, or private endpoint configurations are defined, the account remains globally accessible over the internet.
