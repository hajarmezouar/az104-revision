## Énoncé et corrigé fourni


You are planning to automate the deployment of a virtual machine scale set that is based on the Windows Server Datacenter image.
As part of the deployment process, you must ensure that all virtual machines created in the scale set automatically have the required web server components installed at provisioning time.
Based on this requirement, determine which two actions you should perform.
Réponses (plusieurs réponses possibles)
☐ Create a new virtual machine scale set in the Azure portal.
**☑** Upload a configuration script that installs the required web server components.
**☑** Update the `extensionProfile` section of the Azure Resource Manager (ARM) template to run the configuration during provisioning.
☐ Create an Azure Policy to enforce the installation of web server components.
☐ Create an Azure Automation account to manage post-deployment configuration.
Explication
`Upload a configuration script that installs the required web server components` is correct because to automate the installation of web server components (e.g., IIS), you need a PowerShell or DSC (Desired State Configuration) script that defines those installation steps.
`Update the extensionProfile section of the Azure Resource Manager (ARM) template to run the configuration during provisioning` is correct because this section allows you to add VM extensions such as Custom Script Extension or DSC Extension, which execute your uploaded configuration script on each VM instance when the scale set is deployed.
`Create a new virtual machine scale set in the Azure portal` is incorrect for this purpose alone, as it doesn’t inherently ensure web server components are installed unless you use extensions or post-deployment scripts.
`Create an Azure Policy to enforce the installation of web server components` is incorrect because policies are used to enforce resource configurations or compliance—not to deploy software like a web server on VMs.
`Create an Azure Automation account to manage post-deployment configuration` is incorrect because Automation Accounts are used for orchestrating broader tasks like runbooks across Azure, not for provisioning software during VM creation in scale sets.
