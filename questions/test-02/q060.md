## Énoncé et corrigé fourni


You have an Azure subscription that contains virtual machines running Windows Server, configured as shown in the table below:
You create the following DNS resources:
- A public Azure DNS zone named adatum.com
- A private Azure DNS zone named contoso.com
You then create a virtual network link between the contoso.com private DNS zone and VNET2, with auto-registration enabled.
True or False:
`"When VM3 starts, a DNS record for VM3 is created in the adatum.com DNS zone."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because VM3 is in VNET2, and VNET2 is linked only to the contoso.com private DNS zone with auto-registration enabled. While VM3 has the DNS suffix adatum.com configured at the OS level, this suffix is ignored for auto-registration purposes. Also, adatum.com is a public Azure DNS zone, and Azure does not support auto-registration into public DNS zones. Therefore, when VM3 is registered through the private DNS zone auto-registration process, its DNS record will be created in contoso.com, not adatum.com.
