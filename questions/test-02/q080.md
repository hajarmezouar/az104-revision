## Énoncé et corrigé fourni


You are planning to upload the disk files of a virtual machine to a storage account named account1 from your on-premises network. The on-premises environment uses the public IP address range 131.107.1.0/24. These disk files will later be used to provision an Azure virtual machine named VM1, which will be connected to a virtual network called VNet1. The address space of VNet1 is 192.168.0.0/24.
You need to configure account1 to meet the following requirements:
- Allow disk files to be uploaded from the on-premises network.
- Allow the uploaded disks to be attached to VM1 after provisioning.
- Block all other access to the storage account.
Which two actions should you perform?
Réponses (plusieurs réponses possibles)
☐ From the Networking blade of account1, select Allow Azure services on the trusted services list to access this storage account.
☐ From the Service endpoints blade of VNet1, add a service endpoint.
**☑** From the Networking blade of account1, add the 131.107.1.0/24 IP address range.
☐ From the Networking blade of account1, add VNet1.
**☑** From the Networking blade of account1, select Enabled from selected virtual networks and IP addresses.
Explication
`From the Networking blade of account1, add the 131.107.1.0/24 IP address range` is the correct answer here. Since your on-premises network uses this public IP range, adding it allows connectivity from your location so you can upload the disk files to the Azure storage account. Without adding this IP range, access from your on-premises environment would be denied.
`From the Networking blade of account1, select Enabled from selected virtual networks and IP addresses` is also correct because it activates network-level restrictions and ensures that only the explicitly defined IP ranges and virtual networks have access to the storage account. This setting is necessary to prevent all other access, fulfilling the security requirement.
`From the Networking blade of account1, select Allow Azure services on the trusted services list to access this storage account` is incorrect because this would allow broader Azure services to access the storage account, which violates the requirement to prevent all other access. It provides platform-wide service access beyond your defined IPs and VNets.
`From the Service endpoints blade of VNet1, add a service endpoint` is incorrect because service endpoints do not help in enabling access from on-premises networks. They are intended for traffic routing from Azure virtual networks only.
`From the Networking blade of account1, add VNet1` is incorrect because there is no need to allow VNet1 directly for VM1 to attach the disk during provisioning. Azure handles disk attachment through trusted services internally, and access from the VM at that point is not needed.
