## Énoncé et corrigé fourni


You have an Azure subscription that contains the following resource groups:
- RG1: Region: East US
- RG2: Region: West US
You create the following Azure Resource Manager (ARM) template named deploy.json.
{
"$schema": "https://schema.management.azure.com/schemas/2015-01-01/deploymentTemplate.json#",
"contentVersion": "1.0.0.0",
"parameters": {},
"variables": {},
"resources": [
{
"type": "Microsoft.Resources/resourceGroups",
"apiVersion": "2018-05-01",
"location": "eastus",
"name": "[concat('RG', copyIndex())]",
"copy": {
"name": "copy",
"count": 4
}
}
],
"outputs": {}
}
You deploy the template by running the following cmdlet:
`New-AzSubscriptionDeployment -Location westus -TemplateFile deploy.json`
True or False:
`“The template creates a resource group named RG0 in the East US Azure region.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer here. The ARM template defines a resource group resource type (`Microsoft.Resources/resourceGroups`) and uses a `copy` loop to create 4 resource groups named RG0, RG1, RG2, and RG3. The key detail is the `"location": "eastus"` line inside the resource definition, which specifies that each of these resource groups should be created in the East US Azure region, regardless of the location specified when deploying the template.
The command used to deploy the template is:
New-AzSubscriptionDeployment -Location westus -TemplateFile deploy.json
The `-Location westus` in this context refers to the location of the deployment metadata, not the location of the resources being created. Therefore, the deployment itself is tracked in West US, but the actual resource groups defined in the template are created in East US as specified in the `"location"` property of the resource block.
Hence, RG0 is created in East US, making the statement true.
