## Énoncé et corrigé fourni


You have an Azure App Service plan named AppServicePlanA that is configured with the Standard pricing tier.
You need to configure the plan so that it automatically increases its instance count whenever the web app’s CPU utilization exceeds 80 percent.
Which configuration setting should you enable for AppServicePlanA to achieve this behavior?
Réponses:
☐ Automatic scaling configured in the Scale out settings
**☑** Rule-based scaling configured in the Scale out settings
☐ Premium P1 selected under the Scale up (App Service plan) settings
☐ Standard S1 selected under the Scale up (App Service plan) settings
☐ Manual scaling configured in the Scale out settings
Explication
`Rule-based scaling configured in the Scale out settings` is the correct answer here. By selecting Rules Based, you can configure specific conditions for automatic scaling, such as when CPU usage exceeds 80 percent. This allows AppServicePlanA to automatically add more instances when the CPU utilization goes above the defined threshold. In this case, a rule can be created to automatically scale out based on CPU performance, which satisfies the requirement.
`Automatic scaling configured in the Scale out settings` is incorrect because it doesn't allow setting specific scaling conditions, such as CPU thresholds.
`Manual scaling configured in the Scale out settings` is incorrect because it requires manual intervention to scale, which does not meet the requirement of automatic scaling when CPU usage exceeds 80 percent.
`Premium P1 selected under the Scale up (App Service plan) settings` and
`Standard S1 selected under the Scale up (App Service plan) settings` are incorrect because these refer to scaling up (increasing the resources of the plan itself), not scaling out (adding more instances) based on a specific condition like CPU usage.
