## Énoncé et corrigé fourni


An Azure subscription contains two resource groups with the following configurations:
Resource group settings
- RG1
- Resource group lock: None
- RG2
- Resource group lock name: Lock
- Lock type: Delete
Resources in RG1
- Storage1
- Type: Storage account
- Lock name: Lock1
- Lock type: Delete
- VNET1
- Type: Virtual network
- Lock name: Lock2
- Lock type: Read-only
- IP1
- Type: Public IP address
- Lock: None
Resources in RG2
- Storage2
- Type: Storage account
- Lock name: Lock1
- Lock type: Delete
- VNET2
- Type: Virtual network
- Lock name: Lock2
- Lock type: Read-only
- IP2
- Type: Public IP address
- Lock: None
Which resources can be moved from RG1 to RG2?
Réponses:
☐ None
☐ IP1 only
☐ IP1 and storage1 only
☐ IP1 and VNET1 only
**☑** IP1, VNET1, and storage1
Explication
`IP1, VNET1, and storage1` is correct. Azure resource locks such as Read-only and Delete are designed to prevent deletion or modification of resources, but they do not block move operations. A Delete lock on a resource (such as storage1) or the target resource group (like RG2) does not prevent resources from being moved into or out of that group. Similarly, a Read-only lock (as applied to VNET1) restricts modifications but still permits the resource to be moved. IP1 has no lock, so it is fully eligible for movement. Since none of the listed locks prohibit the act of moving resources, all three resources — IP1, VNET1, and storage1 — can be moved from RG1 to RG2.
