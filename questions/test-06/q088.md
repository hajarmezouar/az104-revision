## Énoncé et corrigé fourni


An Azure subscription contains the following users:
- User1 – Member of Group1
- User2 – Member of Group2
- User3 – Member of Group3
The groups are configured as follows:
- Group1 – Type: Security
- Group2 – Type: Security
- Group3 – Type: Microsoft 365
All three groups are enabled for Microsoft Entra role assignments.
You also have a resource group named RG1. The access control (IAM) configuration for RG1 is shown in the exhibit.
True or False:
`"You can assign User3 the Owner role for RG1 by adding Group3 as a member of Group1."`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer because Azure role assignments do not support nested groups when the nested group is a Microsoft 365 group. In this scenario, Group3 is a Microsoft 365 group, and even though Group1 is assigned the Owner role for RG1, adding Group3 as a member of Group1 will not grant the Owner role to User3. This is because Microsoft Entra ID (Azure AD) does not support nested group evaluation for Microsoft 365 groups in role assignments.
Reference(s):
- https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/groups-concept#limitations-of-using-groups-in-azure-ad-roles
- https://learn.microsoft.com/en-us/entra/identity/users/directory-service-limits-restrictions
