## Énoncé et corrigé fourni


A Microsoft Entra tenant contains the following users:
- User1
- Member of: Group1
- Assigned license: Microsoft Entra ID P2
- User2
- Member of: Group2
- Assigned license: None
- User3
- Member of: No groups
- Assigned license: Microsoft Entra ID P2
- User4
- Member of: No groups
- Assigned license: None
The tenant also contains the following groups and group relationships:
- Group1
- Member of: No groups
- Assigned license: None
- Group2
- Member of: Group3
- Assigned license: Microsoft Entra ID P2
- Group3
- Member of: Group4
- Assigned license: None
- Group4
- Member of: No groups
- Assigned license: Microsoft Entra ID P2
Based on the tenant configuration shown above, which `groups` are eligible to be deleted from Microsoft Entra ID?
Réponses:
☐ Group1 only
☐ Group4 only
**☑** Group1 and Group3 only
☐ Group1, Group2, Group3, and Group4
Explication
`Group1 and Group3 only` is the correct answer because both groups do not have any licenses directly assigned to them. According to Microsoft Entra documentation, a group cannot be deleted if it has licenses directly assigned. Group1 and Group3 meet the criteria for deletion: Group1 has no assigned license, and Group3 is only a member of another group but does not itself have any license directly assigned.
`Group4 only` is incorrect because Group4 has a Microsoft Entra ID P2 license assigned directly, which prevents it from being deleted until the license is removed.
`Group1 only` is incorrect because while Group1 can be deleted, Group3 can also be deleted, so this answer is incomplete.
`Group1, Group2, Group3, and Group4` is incorrect because Group2 and Group4 both have licenses directly assigned, which disqualifies them from deletion until those licenses are removed.
Reference(s):
- https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users
- https://learn.microsoft.com/en-us/entra/fundamentals/licensing-groups-resolve-problems#when-a-licensed-group-is-deleted
