## Énoncé et corrigé fourni


You have an Azure subscription named Subscription1 that has the following vCPU quotas in the West US region:
- Standard BS Family vCPUs: 20 (0 currently used)
- Standard D Family vCPUs: 20 (0 currently used)
- Total Regional vCPUs: 20 (0 currently used)
The subscription currently contains the following virtual machines deployed in West US:
- VM1
- Size: Standard_B2ms
- vCPUs: 2
- Status: Running
- VM2
- Size: Standard_B16ms
- vCPUs: 16
- Status: Stopped (Deallocated)
You now plan to deploy the following additional virtual machines:
True or False:
`“You can deploy VM3 to West US.”`
Réponses:
**☑** True
☐ False
Explication
`True` is correct. In this scenario, VM1 is running and uses 2 vCPUs. VM2 is in a Stopped (Deallocated) state, but it still counts against the vCPU quota because Azure reserves resources for any provisioned (even if deallocated) VM. This brings the current vCPU usage to:
- VM1: 2 vCPUs
- VM2: 16 vCPUs
- Total usage: 18 out of 20 vCPUs (under the Total Regional vCPU quota)
VM3 requires 2 vCPUs, which would increase total usage to exactly 20, matching the quota but not exceeding it. Therefore, the deployment is allowed.
Additionally, the Standard BS Family vCPU quota is 20. VM2 (Standard_B16ms) is a B-series VM, so it counts toward this quota too, alongside VM1. Current usage is therefore 18 vCPUs (VM1's 2 + VM2's 16). Adding VM3 (2 vCPUs from the same family) brings it to exactly 20, which is also allowed.
