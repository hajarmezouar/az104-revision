## Énoncé et corrigé fourni


You manage an Azure Storage account named datastore01.
The account includes a blob container named archivecontainer.
You must ensure that any new blobs uploaded to archivecontainer cannot be altered or deleted for a period of one year after they are created.
Which configuration should you apply to meet this requirement?
Réponses:
☐ The Access control (IAM) settings
**☑** An access policy
☐ The access level
☐ The access tier
Explication
`An access policy` is the correct answer because immutable storage in Azure Blob Storage is configured using immutability policies (such as time-based retention or legal hold), which are set at the container level. Although technically this is not the same as a "stored access policy" used with SAS tokens, the term "access policy" here refers to the immutability policy configuration under the container’s "Access policy" settings in the Azure portal. By configuring a time-based retention policy under these settings, you can ensure that any new blobs added to the container cannot be modified or deleted for one year, thereby satisfying the requirement for data immutability.
`The Access control (IAM) settings` is incorrect because IAM controls role-based access to storage resources, defining who can read, write, or manage resources, but it does not enforce data immutability or retention policies.
`The access level` is incorrect because it defines whether the container and blobs can be publicly accessed (e.g., private, blob, or container level), but it has no impact on the ability to modify or retain content.
`The access tier` is incorrect because it specifies the performance and cost model of the blob data (Hot, Cool, Cold, or Archive). It does not prevent modifications or define retention behavior.
