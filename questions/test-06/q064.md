## Énoncé et corrigé fourni


You have an Azure subscription named Subscription1 that has the following vCPU quotas in the West US region:
- Standard BS Family vCPUs: 20 (0 currently used)
- Standard D Family vCPUs: 20 (0 currently used)
- Total Regional vCPUs: 20 (0 currently used)
The subscription currently contains the following virtual machines deployed in West US:
- VM1
- Size: Standard_B2ms
- vCPUs: 2
- Status: Running
- VM2
- Size: Standard_B16ms
- vCPUs: 16
- Status: Stopped (Deallocated)
You now plan to deploy the following additional virtual machines:
True or False:
`“You can deploy VM5 to West US.”`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because the Total Regional vCPU quota in the West US region is 20 vCPUs. This quota accounts for all allocated and deallocated virtual machines in the region.
The current vCPU usage is as follows:
- VM1: 2 vCPUs (Running)
- VM2: 16 vCPUs (Stopped/Deallocated)
Even though VM2 is deallocated, its 16 vCPUs still count toward the regional vCPU quota because Azure reserves these resources for the VM.
This means the total vCPU usage stands at:
2 vCPUs (VM1) + 16 vCPUs (VM2) = 18 vCPUs
VM5 requires 16 vCPUs. Adding these would result in:
2 vCPUs (VM1) + 16 vCPUs (VM2) + 16 vCPUs (VM5) = 34 vCPUs
This far exceeds the 20 vCPU quota for the West US region, making it impossible to deploy VM5 without increasing the quota or deallocating other virtual machines.
