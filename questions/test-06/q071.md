## Énoncé et corrigé fourni


You have an Azure subscription that includes the following resources:
- VNET1: A virtual network in resource group RG1
- VM1: A virtual machine in resource group RG1
A Not allowed resource types Azure Policy is assigned to RG1 with enforcement enabled. The policy blocks the following resource types:
- Microsoft.Network/virtualNetworks
- Microsoft.Compute/virtualMachines
You need to deploy a new virtual machine named VM2 in RG1 and connect it to VNET1.
What action must you take first?
Réponses:
**☑** Remove Microsoft.Compute/virtualMachines from the policy.
☐ Add a subnet to VNET1.
☐ Remove Microsoft.Network/virtualNetworks from the policy.
☐ Create an Azure Resource Manager template.
Explication
`Remove Microsoft.Compute/virtualMachines from the policy` is the correct answer. The Not allowed resource types policy assigned to RG1 explicitly prevents the creation of resources with type `Microsoft.Compute/virtualMachines`, which includes any virtual machines. Since the goal is to create a new VM named VM2 in RG1, this policy must first be adjusted to allow VM creation. Otherwise, any deployment attempt for a VM (whether through portal, script, or ARM template) will be blocked due to the policy enforcement.
`Add a subnet to VNET1` is incorrect because the presence or absence of a subnet does not address the core issue. Even if VNET1 had a valid subnet, the policy blocks VM creation entirely in RG1, making this step irrelevant at this point.
`Remove Microsoft.Network/virtualNetworks from the policy` is incorrect because there is no requirement to create a new virtual network—VNET1 already exists and is intended to be used. The VM can be connected to an existing VNet as long as the policy allows VM creation. Removing this restriction isn't necessary to create the VM.
`Create an Azure Resource Manager template` is incorrect because using an ARM template will still fail if the policy prohibits creating the specified resource types. Azure Policy enforcement blocks resource creation regardless of the method used—portal, CLI, PowerShell, or ARM templates.
