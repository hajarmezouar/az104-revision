## Énoncé et corrigé fourni


An Azure subscription contains two resource groups with the following configurations:
Resource group settings
- RG1
- Resource group lock: None
- RG2
- Resource group lock name: Lock
- Lock type: Delete
Resources in RG1
- Storage1
- Type: Storage account
- Lock name: Lock1
- Lock type: Delete
- VNET1
- Type: Virtual network
- Lock name: Lock2
- Lock type: Read-only
- IP1
- Type: Public IP address
- Lock: None
Resources in RG2
- Storage2
- Type: Storage account
- Lock name: Lock1
- Lock type: Delete
- VNET2
- Type: Virtual network
- Lock name: Lock2
- Lock type: Read-only
- IP2
- Type: Public IP address
- Lock: None
Which resources can be moved from RG2 to RG1?
Réponses:
☐ None
☐ IP2 only
☐ IP2 and storage2 only
☐ IP2 and VNET2 only
**☑** IP2, VNET2, and storage2
Explication
`IP2, VNET2, and storage2` is correct as Locks are designed for any update or removal. In this case, we want to move only, we are not deleting, and we are not changing anything in the resource.
In the previous question, we were able to move all resources from RG1 to RG2. Similarly, we will be able to move IP2, VNET2, and storage2 from RG2 to RG1.
Attempting to move resources from RG2 to RG1
After successful movement, RG2 resources
After successful movement, RG1 resources

- https://docs.microsoft.com/en-us/azure/azure-resource-manager/management/lock-resources
