## Énoncé et corrigé fourni


You have an Azure subscription that hosts several resources accessed by users from two locations:
- Users working from home connect to Azure by using a point-to-site (P2S) VPN.
- Users at customer locations connect to Azure by using site-to-site (S2S) VPNs.
There is a line-of-business application named App1 that runs on multiple Azure virtual machines.
All the virtual machines run Windows Server 2016.
You must ensure that incoming connections to App1 are evenly distributed across all the virtual machines.
Which two Azure services can you use to meet this requirement?
Réponses (plusieurs réponses possibles)
**☑** an internal load balancer
☐ a public load balancer
☐ an Azure Content Delivery Network (CDN)
☐ Traffic Manager
**☑** an Azure Application Gateway
Explication
`an internal load balancer` is the correct answer because it distributes incoming traffic evenly across virtual machines within the same virtual network. Internal Load Balancers are used when applications are accessed only internally and do not require public internet exposure. This matches the scenario where users are connecting through VPNs, either point-to-site or site-to-site, and need internal routing of traffic to backend virtual machines hosting App1.
`an Azure Application Gateway` is also correct because it is a layer-7 (application layer) load balancer that can intelligently route traffic based on HTTP/HTTPS requests. It is suitable for web applications like App1, providing features such as URL-based routing, SSL termination, and session affinity, ensuring optimized and secure delivery of requests to the virtual machines hosting App1.
`a public load balancer` is incorrect because it distributes incoming traffic from public IP addresses. In this scenario, the application is accessed internally through VPN connections rather than from the public internet.
`an Azure Content Delivery Network (CDN)` is incorrect because CDN is designed to cache and deliver static content like images, videos, and scripts globally. It does not handle traffic distribution to backend virtual machines for business applications like App1.
`Traffic Manager` is incorrect because it operates at the DNS level and is used to direct users to different endpoints based on rules like geographic location or endpoint health. It does not distribute traffic across virtual machines within the same virtual network.
