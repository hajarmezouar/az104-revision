## Énoncé et corrigé fourni


You have an Azure subscription named Subscription1 that has the following vCPU quotas in the West US region:
- Standard BS Family vCPUs: 20 (0 currently used)
- Standard D Family vCPUs: 20 (0 currently used)
- Total Regional vCPUs: 20 (0 currently used)
The subscription currently contains the following virtual machines deployed in West US:
- VM1
- Size: Standard_B2ms
- vCPUs: 2
- Status: Running
- VM2
- Size: Standard_B16ms
- vCPUs: 16
- Status: Stopped (Deallocated)
You now plan to deploy the following additional virtual machines:
True or False:
`“You can deploy VM4 to West US.”`
Réponses:
☐ True
**☑** False
Explication
`False` is correct as the Total Regional vCPUs quota in West US is capped at 20 vCPUs. This quota represents the maximum total vCPUs across all VM sizes, regardless of whether a virtual machine is running or stopped (deallocated).
In the current scenario:
- VM1 is consuming 2 vCPUs (Running).
- VM2 is Stopped (Deallocated) but still counts towards the total regional vCPU quota with 16 vCPUs reserved.
This results in:
2 vCPUs (VM1) + 16 vCPUs (VM2) = 18 vCPUs
This leaves only 2 vCPUs available under the regional quota.
VM4 requires 4 vCPUs, which would bring the total to:
2 vCPUs (VM1) + 16 vCPUs (VM2) + 4 vCPUs (VM4) = 22 vCPUs
This exceeds the total regional vCPU quota of 20 vCPUs, making the deployment of VM4 impossible under the current quota limits.

https://learn.microsoft.com/en-us/azure/virtual-machines/quotas?tabs=cli
https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/azure-subscription-service-limits
