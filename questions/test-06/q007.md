## Énoncé et corrigé fourni


Your environment includes an on-premises Active Directory Domain Services (AD DS) domain with the identities listed below:
- User1 is a user account located in OU2.
- User2 is a user account located in OU1.
- Group1 is a global security group that includes User1 and is located in OU1.
You have an Azure subscription that contains a storage account named storage1.
The Azure Files shares in storage1 use AD DS as the identity source, and the default share-level permissions are configured to allow access for all authenticated users and groups.
You create an Azure Files share named share1 and assign the following roles:
- User2 is assigned the Storage File Data SMB Share Reader role.
- Group1 is assigned the Storage File Data SMB Share Contributor role.
You also have a Microsoft Entra tenant that includes a cloud-only user named User3.
Microsoft Entra Connect is configured to synchronize OU1 from the on-premises AD DS domain to the Microsoft Entra tenant.
True or False:
`"User2 can access content in share1."`
Réponses:
**☑** True
☐ False
Explication
`True` is correct.
User2 can access share1 because User2 is located in OU1, and OU1 is synchronized to Microsoft Entra ID. User2 is also explicitly assigned the Storage File Data SMB Share Reader role on share1, which grants read access at the Azure Files share level.
Additionally, the question states that the default share-level permissions are configured to allow access for all authenticated users and groups. Therefore, even without the explicit RBAC assignment, User2 could still be allowed at the share level if User2 can authenticate against the associated AD DS domain and the default permission grants sufficient access.
However, Azure Files access is controlled by both share-level permissions and NTFS file/directory permissions. Therefore, actual access to the content also depends on the applicable NTFS ACLs. In this question, no restrictive NTFS ACL is mentioned, so User2 can access the content in share1.
