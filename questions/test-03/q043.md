## Énoncé et corrigé fourni


You have two Azure subscriptions named Subscription1 and Subscription2.
Each subscription is associated with a different Microsoft Entra tenant.
The resources are configured as follows:
- Subscription1
- Contains a virtual network named VNet1
- VNet1 has an address space of 10.0.0.0/16
- VNet1 contains a virtual machine named VM1
- Subscription2
- Contains a virtual network named VNet2
- VNet2 has an address space of 10.10.0.0/24
- VNet2 contains a virtual machine named VM2
You need to establish network connectivity between VNet1 and VNet2.
What should you do first?
Réponses:
☐ Move the virtual machine VM1 from Subscription1 to Subscription2.
**☑** Create and configure virtual network gateways for the virtual networks.
☐ Move the virtual network VNet1 into Subscription2.
☐ Change the IP address range assigned to VNet2.
Explication
`Create and configure virtual network gateways for the virtual networks` is correct because to connect VNet1 in Subscription1 to VNet2 in Subscription2, you need to set up VNet-to-VNet connectivity across different subscriptions and tenants. The recommended approach for achieving this connection is to provision virtual network gateways in each virtual network and establish a VPN connection between them. This approach supports cross-subscription and cross-tenant connections.
`Move the virtual machine VM1 from Subscription1 to Subscription2` is incorrect because moving the VM does not address the need to connect the virtual networks across different subscriptions and tenants.
`Move the virtual network VNet1 into Subscription2` is incorrect because moving the entire virtual network to the same subscription is unnecessary when you can achieve connectivity through virtual network gateways.
`Change the IP address range assigned to VNet2` is incorrect because there is no overlapping IP address space that would prevent connectivity; both address spaces are already compatible.
Reference(s):
- https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-howto-vnet-vnet-resource-manager-portal
