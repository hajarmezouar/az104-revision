## Énoncé et corrigé fourni


Note: This question is part of a series that uses the same overall scenario. Each question in the series proposes a different solution that may or may not satisfy the stated requirement.
You have an Azure subscription that contains 10 virtual networks, each deployed in its own resource group.
Another administrator intends to create multiple network security groups (NSGs) within the subscription.
You must ensure that every newly created NSG automatically blocks TCP traffic on port 8080 between the virtual networks.
Proposed solution: You create a resource lock and apply it at the subscription scope.
Does this solution satisfy the requirement?
Réponses:
☐ Yes
**☑** No
Explication
`No` is the correct answer here. A resource lock is used to prevent accidental deletion or modification of Azure resources, but it does not enforce security rules or configurations, such as network access control. Resource locks are intended to protect resources from changes, not to configure their behavior.
To meet the stated goal of automatically blocking TCP port 8080 between virtual networks whenever a network security group (NSG) is created, you should use Azure Policy. You can create a policy definition that audits or enforces the presence of specific inbound or outbound security rules (such as blocking port 8080) in NSGs and assign that policy at the subscription level.
