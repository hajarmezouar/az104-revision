## Énoncé et corrigé fourni


You have an Azure Storage account named storage1.
You also have two Azure App Service applications named App1 and App2. Both applications run in Azure container instances and both use managed identities.
You must ensure that both App1 and App2 can read blobs stored in storage1. The solution must meet the following requirements:
- Use the fewest possible secrets.
- Ensure that App2 is allowed to read data from storage1 for only the next 30 days.
What should you configure in storage1 for App1?
Réponses:
☐ Configure storage account access keys.
☐ Enable advanced security settings on the storage account.
**☑** Configure role-based access control (RBAC) by using Access control (IAM).
☐ Generate Shared access signatures (SAS)
Explication
`Configure role-based access control (RBAC) by using Access control (IAM)` is correct because Azure Role-Based Access Control (RBAC) enables you to assign the Storage Blob Data Reader role to App1’s managed identity, allowing it to read blobs in storage1 without using secrets like keys or tokens. This meets the requirement to minimize the number of secrets used. RBAC is the most secure and manageable approach for long-term access and works seamlessly with managed identities. While RBAC does not natively support automatic expiration of access after a specific period, that requirement only applies to App2.
`Configure storage account access keys` is incorrect because access keys grant full access to the storage account and must be stored and rotated as secrets, violating the principle of least privilege.
`Enable advanced security settings on the storage account` is incorrect because it enhances storage account protection (e.g., firewalls or encryption), but it is not used to control identity-based read permissions.
`Generate Shared access signatures (SAS)` is incorrect for App1 because it involves generating and managing a token (a secret) and is better suited for time-limited access scenarios. While SAS does support expiration, it requires more overhead compared to RBAC for apps with managed identities.

- https://learn.microsoft.com/en-us/azure/azure-resource-manager/managed-applications/publish-managed-identity#granting-access-to-azure-resources
