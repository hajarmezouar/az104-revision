## Énoncé et corrigé fourni


You have an Azure virtual machine named VM1 that is connected to a virtual network called VNet1. VM1 has the following configuration:
- Subnet: 10.0.0.0/24
- Availability set: AVSet
- Network security group (NSG): None
- Private IP address: 10.0.0.4 (dynamic)
- Public IP address: 40.90.219.6 (dynamic)
You deploy a Standard, internet-facing Azure Load Balancer named slb1.
You need to configure slb1 to allow inbound traffic to VM1, and you are permitted to make any required changes to VM1 during the configuration.
Complete the following statement:
“Before creating a backend pool on slb1, you must ____________________.”
Réponses:
☐ Create and assign an NSG to VM1
**☑** Remove the public IP address from VM1
☐ Change the private IP address of VM1 to static
Explication
`Remove the public IP address from VM1` is the correct answer here. When using a Standard, Internet-facing Azure Load Balancer, virtual machines that are part of the backend pool should not have individual public IP addresses assigned. Instead, all inbound traffic should be directed to the load balancer’s frontend public IP, and the load balancer will distribute that traffic to the VMs in the backend pool.
In this case, VM1 currently has a dynamic public IP address. For proper configuration with Standard SKU Load Balancer, this dynamic public IP should be removed, and the VM should receive traffic only through the load balancer. The Standard Load Balancer also requires a Standard SKU public IP to be assigned to its frontend configuration—not to the individual VM.
`Create and assign an NSG to VM1` is incorrect because NSGs control traffic flow at the subnet or NIC level but are not required to add a VM to a Standard Load Balancer backend pool. While NSGs can be used for security, they are not relevant to this prerequisite.
`Change the private IP address of VM1 to static` is incorrect in this specific scenario because the VM is being added to a Standard Load Balancer in an Internet-facing configuration. In such cases, the VM’s private IP does not need to be static—only the load balancer’s public IP needs to be static and Standard SKU. The private IP requirement typically applies when the load balancer is internal, not Internet-facing.
