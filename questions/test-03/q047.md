## Énoncé et corrigé fourni


You have an on-premises environment that includes a VPN gateway.
Your Azure subscription contains the following resources:
- vgw1 – a virtual network gateway configured for a site-to-site VPN connection to the on-premises network
- storage1 – a storage account using the Standard performance tier
- Vnet1 – a virtual network with forced tunneling enabled
- VM1 – a virtual machine connected to Vnet1
You must guarantee that any traffic originating from VM1 and destined for storage1 travels only across the Microsoft backbone network, and not through the public internet or the on-premises network.
What configuration should you implement?
Réponses:
☐ Azure Peering Service
**☑** service endpoints
☐ Microsoft Entra Application Proxy
☐ Azure Application Gateway
Explication
`service endpoints` is correct because configuring service endpoints for storage1 will ensure that traffic from VM1 to storage1 travels across the Microsoft backbone network. Service endpoints allow private access to Azure services over the Azure backbone network by extending a virtual network's identity to the Azure service. This setup secures the traffic from VM1 to storage1 by keeping it within Microsoft’s network infrastructure.
`Azure Peering Service` is incorrect because it is designed for optimizing internet traffic but does not ensure that traffic stays within the Microsoft backbone for specific resources like storage1.
`Microsoft Entra Application Proxy` is incorrect because it provides secure remote access to on-premises applications, not for managing internal Azure network traffic between resources.
`Azure Application Gateway` is incorrect as it is a layer 7 load balancer for managing HTTP/HTTPS traffic and does not direct traffic over the Microsoft backbone for a virtual machine accessing a storage account.
Reference(s):
- https://learn.microsoft.com/en-us/azure/virtual-network/virtual-network-service-endpoints-overview
