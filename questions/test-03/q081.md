## Énoncé et corrigé fourni


You have an Azure virtual network named VNet1 that is connected to an on-premises network by using a site-to-site VPN. VNet1 includes a single subnet named Subnet1.
Subnet1 is associated with a network security group (NSG) called NSG1. The subnet hosts a basic internal load balancer named ILB1, which has three Azure virtual machines configured in its backend pool.
You need to collect information about the IP addresses that establish connections to ILB1. The collected data must be available for interactive querying directly from the Azure portal.
On which resource should you enable diagnostics?
Réponses:
☐ ILB1
**☑** NSG1
☐ The Azure virtual machines
Explication
`NSG1` is the correct answer here. To collect data about the IP addresses that connect to ILB1, you must monitor network traffic, and the correct way to do this in Azure is by enabling NSG flow logs on the Network Security Group (NSG) associated with the subnet or network interface.
In this case:
- NSG1 is associated with Subnet1, which contains ILB1 and its backend virtual machines.
- Enabling diagnostic settings (NSG flow logs) on NSG1 captures detailed flow-level information such as source IP, destination IP, port, protocol, and action (allow/deny).
- The logs can be sent to a Log Analytics workspace, where you can run interactive queries using Kusto Query Language (KQL) directly from the Azure portal.
`ILB1` is incorrect because while you can enable diagnostics on a load balancer, it captures metrics like health probe status and data throughput, not connection-level details like source IP addresses.
`The Azure virtual machines` is incorrect because enabling diagnostics on the VMs focuses on performance and system logs (e.g., CPU, disk, guest OS), but not on the network flow data you need for this scenario.
