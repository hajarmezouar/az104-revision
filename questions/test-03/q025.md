## Énoncé et corrigé fourni


You have a Microsoft Entra tenant that is linked to the Azure subscriptions shown in the following table.
Within these subscriptions, the following resource groups exist:
- RG1 is in SubA and contains a storage account named storage1.
- RG2 is in SubB and contains a web app named App1.
- RG3 is in SubC and contains a virtual machine named VM1.
Role assignments are configured as follows:
- User1 is assigned the Contributor role at the MG2 management group scope.
- User2 is assigned the Storage Account Contributor role scoped specifically to storage1.
- User3 is assigned the User Access Administrator role at the Tenant Root Group scope.
True or False:
`"User2 can create a new storage account in RG1."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because User2’s Storage Account Contributor role is assigned only at the scope of the existing storage account (storage1). Although this role includes permissions to create storage accounts when assigned at the resource group or subscription level, permissions granted at an individual resource scope do not allow the creation of new sibling resources. Since User2 has no role assignment at the RG1 or subscription scope, they cannot create a new storage account in RG1.
Reference(s):
- https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles
