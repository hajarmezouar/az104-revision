## Énoncé et corrigé fourni


You have an Azure virtual machine named VM1 that is connected to a virtual network called VNet1. VM1 has the following configuration:
- Subnet: 10.0.0.0/24
- Availability set: AVSet
- Network security group (NSG): None
- Private IP address: 10.0.0.4 (dynamic)
- Public IP address: 40.90.219.6 (dynamic)
You deploy a Standard, internet-facing Azure Load Balancer named slb1.
You need to configure slb1 to allow inbound traffic to VM1, and you are permitted to make any required changes to VM1 during the configuration.
Complete the following statement:
“Before you can connect to VM1 from slb1, you must______________________.”
Réponses:
**☑** Create and configure an NSG
☐ Remove the public IP address from VM1
☐ Change the private IP address of VM1 to static
Explication
`Create and configure an NSG` is the correct answer here. In the context of an Internet-facing Standard Load Balancer, after configuring the load balancer and assigning a static, standard public IP to the frontend, you must ensure that traffic is allowed through to the VM. A Network Security Group (NSG) is required to define and permit inbound traffic (such as TCP on port 80 or 443) to the VM or subnet where the VM resides.
By default, no inbound traffic is allowed unless explicitly permitted via an NSG. Without an NSG rule allowing the required traffic, even if the frontend IP and backend pool are configured correctly, the connection to VM1 through slb1 would fail due to traffic being denied at the network layer.
`Remove the public IP address from VM1` is incorrect because this step is only relevant if the VM had a dynamic public IP that conflicted with the Standard Load Balancer setup. Since the public IP has already been properly configured in the prior step, there's no need to remove it again. The focus now is on allowing traffic through to the VM, not modifying its IP configuration.
`Change the private IP address of VM1 to static` is incorrect because this is only required in the context of an internal load balancer or when backend pools rely on consistent internal addressing. For Internet-facing load balancers, private IP settings are not critical for enabling frontend communication. What’s essential is that the NSG allows the traffic to reach the backend VM.
