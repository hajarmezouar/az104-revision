## Énoncé et corrigé fourni


Note: This question is part of a series that uses the same overall scenario. Each question in the series proposes a different solution that may or may not satisfy the stated requirement.
You have an Azure subscription that contains the virtual machines shown in the following table.
You deploy a load balancer with the following characteristics:
- The load balancer is named LB1.
- It is an internal load balancer.
- It uses the Standard SKU.
- It is deployed in VNET1.
You need to ensure that both VM1 and VM2 can be added to the backend pool of LB1.
Proposed solution: You remove the public IP address association from VM2’s network interface.
Does this solution meet the requirement?
Réponses:
**☑** Yes
☐ No
Explication
`Yes` is the correct answer because a Standard Load Balancer can only attach virtual machines that:
- Are in the same location and same virtual network as the Load Balancer.
- Have either a Standard SKU public IP or no public IP.
In this scenario:
- VM1 has no public IP attached, which makes it eligible for the backend pool.
- VM2 has a Basic SKU public IP, which is not compatible with a Standard Load Balancer.
By removing the Basic SKU Public IP from VM2, the virtual machine aligns with the requirements of a Standard Load Balancer and can be added to the backend pool alongside VM1.
