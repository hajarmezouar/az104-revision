## Énoncé et corrigé fourni


You have an Azure subscription that includes a resource group named ResGrp1.
ResGrp1 is located in the West Europe region and is used to host temporary resources for a project.
The resource group contains the following resources:
- VM1 is a virtual machine deployed in the North Europe region.
- RGV1 is a Recovery Services vault located in North Europe.
- SQLDB01 is a SQL Server running on an Azure virtual machine in North Europe.
- sa001 is a storage account deployed in West Europe.
The virtual machine SQLDB01 is configured to be backed up to the Recovery Services vault RGV1.
After the project is completed, you attempt to delete ResGrp1 from the Azure portal, but the deletion operation fails.
You need to successfully remove ResGrp1.
What should you do first?
Réponses:
☐ Delete the VM1 virtual machine
☐ Delete the sa001 storage account
**☑** Stop the backup of SQLDB01
☐ Stop the VM1 virtual machine
Explication
`Stop the backup of SQLDB01` is correct because the deletion of a resource group that contains a Recovery Services vault with active backup jobs or protected items will fail. In this scenario, SQLDB01 is backed up to RGV1, which means there are active backup items associated with it. To successfully delete ResGrp1, you first need to stop the backup for SQLDB01 and delete any protected items from the Recovery Services vault (RGV1). Once the backup is stopped and protected items are removed, ResGrp1 can be deleted.
`Delete the VM1 virtual machine` is incorrect because deleting VM1 would not impact the active backup configuration associated with SQLDB01 in RGV1. The deletion of the resource group fails due to the active backup in the Recovery Services vault, not because of the presence of VM1.
`Delete the sa001 storage account` is incorrect because deleting the storage account in a different region (West Europe) does not address the active backup in RGV1. The storage account (sa001) is unrelated to the backup process of SQLDB01 and does not prevent the deletion of the resource group.
`Stop the VM1 virtual machine` is incorrect because stopping the virtual machine does not affect the backup status in the Recovery Services vault. The issue lies with the active backup of SQLDB01, not with the state of VM1.
