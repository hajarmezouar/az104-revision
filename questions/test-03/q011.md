## Énoncé et corrigé fourni


Note: This question is part of a series that uses the same overall scenario. Each question in the series proposes a different solution that may or may not satisfy the stated requirement.
You have an Azure subscription that contains the virtual machines shown in the following table.
You deploy a load balancer with the following characteristics:
- The load balancer is named LB1.
- It is an internal load balancer.
- It uses the Standard SKU.
- It is deployed in VNET1.
You need to ensure that both VM1 and VM2 can be added to the backend pool of LB1.
Proposed solution: You create a Basic SKU public IP address, associate it with the network interface of VM1, and then start VM1.
Does this solution meet the requirement?
Réponses:
☐ Yes
**☑** No
Explication
`No` is the correct answer here. For a Standard SKU load balancer, all virtual machines in the backend pool must be within the same region and connected to the same virtual network (VNET) as the load balancer itself. Additionally, they must either have a Standard SKU public IP address or no public IP address at all. In this scenario, associating a Basic SKU public IP address to VM1 does not meet the requirements for the Standard SKU load balancer. Therefore, this configuration does not allow VM1 and VM2 to be added to the backend pool of LB1.
Reference(s):
- https://learn.microsoft.com/en-us/azure/load-balancer/backend-pool-management#limitations
