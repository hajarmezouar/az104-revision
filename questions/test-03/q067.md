## Énoncé et corrigé fourni


You have four Azure virtual machines with the following configurations:
- VM1 – IP address 10.1.0.4, connected to VNET1/Subnet1
- VM2 – IP address 10.1.10.4, connected to VNET1/Subnet2
- VM3 – IP address 172.16.0.4, connected to VNET2/SubnetA
- VM4 – IP address 10.2.0.8, connected to VNET3/SubnetB
A DNS service is installed on VM1.
You configure the DNS server settings on each virtual network to use a custom DNS server with the IP address 10.1.0.4.
You need to ensure that all the virtual machines can resolve DNS names by using the DNS service on VM1.
What action should you take?
Réponses:
☐ Add service endpoints on VNET2 and VNET3.
**☑** Configure peering between VNET1, VNET2, and VNET3.
☐ Add service endpoints on VNET1.
☐ Configure a conditional forwarder on VM1.
Explication
`Configure peering between VNET1, VNET2, and VNET3` is the correct option because DNS queries sent to a custom DNS server (VM1 in this case) require network connectivity between the virtual networks. Virtual network peering allows resources in different VNets to communicate seamlessly. Once peering is configured, all DNS traffic can route correctly through VM1.
`Add service endpoints on VNET2 and VNET3` is incorrect because service endpoints are used for secure connections to Azure services like Storage or SQL, not for enabling DNS resolution between VNets.
`Add service endpoints on VNET1` is incorrect for the same reason, as service endpoints don't facilitate cross-VNet DNS resolution.
`Configure a conditional forwarder on VM1` is incorrect because a conditional forwarder directs DNS queries to specific DNS servers based on domain names. However, without VNet peering, the DNS traffic wouldn't route between VNets.
