## Énoncé et corrigé fourni


You have an Azure Storage account named storage1.
You also have two Azure App Service applications named App1 and App2. Both applications run in Azure container instances and both use managed identities.
You must ensure that both App1 and App2 can read blobs stored in storage1. The solution must meet the following requirements:
- Use the fewest possible secrets.
- Ensure that App2 is allowed to read data from storage1 for only the next 30 days.
What should you configure in storage1 for App2?
Réponses:
☐ Configure storage account access keys.
☐ Enable advanced security settings on the storage account.
☐ Configure role-based access control (RBAC) by using Access control (IAM).
**☑** Generate Shared access signatures (SAS).
Explication
`Generate Shared access signatures (SAS)` is correct because it enables time-bound access by allowing you to generate a token that grants App2 read access to blobs in storage1 with an exact expiration, such as 30 days. This satisfies the requirement to limit App2’s access duration. While a SAS token is considered a secret, it’s the most practical built-in option for temporary access enforcement. It avoids the need for manual revocation logic that would be required with IAM-based roles.
`Configure storage account access keys` is incorrect because they provide full control over the storage account and are not time-limited, making them unsuitable for scoped or temporary access.
`Enable advanced security settings on the storage account` is incorrect as it does not control time-limited access and does not apply to managed identity permissions.
`Configure role-based access control (RBAC) by using Access control (IAM)` is incorrect for App2 because RBAC does not natively support automated expiration of permissions. You would need external tooling like scripts or Azure PIM to revoke access after 30 days, which is less direct than a SAS token with an expiration.

- https://learn.microsoft.com/en-us/azure/storage/common/authorize-data-access?tabs=blobs
