## Énoncé et corrigé fourni


Note: This question is part of a series that uses the same overall scenario. Each question in the series proposes a different solution that may or may not satisfy the stated requirement.
You have an Azure subscription that contains the virtual machines shown in the following table.
You deploy a load balancer with the following characteristics:
- The load balancer is named LB1.
- It is an internal load balancer.
- It uses the Standard SKU.
- It is deployed in VNET1.
You need to ensure that both VM1 and VM2 can be added to the backend pool of LB1.
Proposed solution: You create two public IP addresses using the Standard SKU, and you assign one Standard SKU public IP address to the network interface of each virtual machine.
Does this solution meet the requirement?
Réponses:
**☑** Yes
☐ No
Explication
`Yes` is the correct answer here. The load balancer in question has a Standard SKU, which requires any associated virtual machines in the backend pool to either have no public IP or a Standard SKU public IP. In this scenario, by creating Standard SKU public IP addresses and associating them with VM1 and VM2, you meet the requirement for compatibility with the Standard SKU load balancer.
For Standard SKU load balancers, virtual machines added to the backend pool must be within the same virtual network and location. Moreover, it’s important that, if public IPs are present, they are also of the Standard SKU type to ensure compatibility with the Standard SKU load balancer.
