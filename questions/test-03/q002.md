## Énoncé et corrigé fourni


You have a Microsoft Entra tenant named apexcore.com.
There are two external partner organizations: ironclad.com and bluerock.com.
Only ironclad.com is configured as a connected organization in Microsoft Entra.
You create an access package as shown in the below exhibit.
The external user lifecycle settings are configured so that when an external user loses their last access package assignment:
- The user is blocked from signing in.
- The user is removed from the directory after 30 days.
True or False:
`“After the 365-day assignment period ends, users from ironclad.com will be removed from Group1.”`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer. When you assign `ironclad` users to Group1 through an access package, their assignment is set to expire after 365 days. At that point, the users’ access package assignment expires, which means:
- They lose access to Group1 and other resources tied to the package.
- Their membership in Group1 is revoked immediately at expiration.
However, this is not the same as being “removed” from the tenant. The external user lifecycle settings add another step:
- After the assignment expires, external users remain in the tenant directory for an additional 30 days.
- During that time, they cannot access Group1 because their assignment has expired, but their guest account still exists in the directory.
- Only after day 395 (365 + 30) are they actually removed from the directory, which finalizes their removal from all groups.
