## Énoncé et corrigé fourni


You have an Azure subscription that includes two storage accounts named contoso101 and contoso102.
The subscription also contains two virtual machines with the following configurations:
- VM1 is connected to VNet1/Subnet1 and uses a Basic public IP address SKU.
- VM2 is connected to VNet1/Subnet2 and uses a Standard public IP address SKU.
Within VNet1, service endpoints are configured as follows:
- Microsoft.AzureActiveDirectory is enabled on Subnet2.
- Microsoft.Storage is enabled on Subnet1.
A service endpoint policy named Policy1 is created for the Microsoft.Storage service. The policy allows access only to the storage account contoso101. The policy is associated with subnets that have Microsoft.Storage service endpoints enabled.
True or False:
`“VM2 can access contoso101.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer. Service endpoint policies are always scoped to the subnet where they are applied, meaning they only control traffic originating from that specific subnet. In this scenario, the Microsoft.Storage service endpoint and its associated policy are applied to Subnet1, which contains VM1. Subnet2, where VM2 resides, has only an Azure Active Directory service endpoint and no storage endpoint or policy applied. This means the policy on Subnet1 does not restrict VM2’s traffic. By default, subnets in the same virtual network can communicate freely unless explicit network security groups or custom routes block that communication, and no such restrictions are mentioned here.
Because the question also does not state that the storage account firewall is locked down to specific networks, we assume the default configuration of allowing traffic from all networks. Under these conditions, VM2 can still reach contoso101 using the storage account’s public endpoint, bypassing the need for a storage service endpoint or policy. The idea that Subnet1’s policy would block all other subnets even via public endpoints, is a common misconception; Microsoft’s documentation makes clear that service endpoint policies only affect traffic from the subnets to which they are applied. Therefore, the correct choice is that VM2 can indeed access contoso101.
