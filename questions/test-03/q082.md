## Énoncé et corrigé fourni


You manage an Azure subscription in which you create an Azure Container Registry (ACR) and build a container image locally.
You plan to upload the container image to the Azure Container Registry by using the Azure Command-Line Interface (CLI).
After successfully signing in to the container registry, what should you do next to prepare the image for upload?
Réponses:
**☑** Assign a tag to the container image that includes the container registry’s login server name.
☐ Display a list of container images that already exist in the container registry.
☐ Deploy a container group.
☐ Configure a YAML file.
Explication
`Assign a tag to the container image that includes the container registry’s login server name` is the correct answer here. After signing in to an Azure Container Registry (ACR), the next required step to push a container image is to tag the image using the registry’s login server URL. This tag identifies the destination registry and repository for the image. The format typically looks like:
az acr login --name <registryName>
docker tag <localImageName> <registryName>.azurecr.io/<repositoryName>:<tag>
docker push <registryName>.azurecr.io/<repositoryName>:<tag>This step is necessary because Docker uses the tag to determine where the image should be pushed. Without tagging the image with the correct registry address, the `docker push` command will not know the target location.
`Display a list of container images that already exist in the container registry` is incorrect because it does not help in preparing an image for upload.
`Deploy a container group` is incorrect because this step would come after the image is already pushed and available in the container registry.
`Configure a YAML file` is incorrect because YAML files are typically used for defining deployments in Kubernetes or other orchestration platforms, not for pushing container images.
