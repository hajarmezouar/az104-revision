## Énoncé et corrigé fourni


You have a virtual network named VNET1 that includes the following subnets:
You also have the following Azure virtual machines with the listed network configurations:
For NSG1, you configure the following inbound security rule:
- Priority: 101
- Source: 10.10.2.0/24
- Destination: 10.10.1.0/24
- Destination port: TCP 1433
- Action: Allow
For NSG2, you configure the following inbound security rule:
- Priority: 125
- Source: 10.10.2.5
- Destination: 10.10.1.5
- Destination port: TCP 1433
- Action: Block
True or False:
`“VM2 can connect to the TCP port 1433 services on VM1.”`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer because the traffic from VM2 to VM1 on TCP port 1433 must be allowed by both NSGs in the inbound path. For inbound traffic to VM1, Azure evaluates the subnet-level NSG first and then the NIC-level NSG. NSG1 allows TCP 1433 traffic from 10.10.2.0/24 to 10.10.1.0/24, so the traffic is allowed at the subnet level. However, NSG2, which is associated with VM1’s NIC, explicitly blocks TCP 1433 traffic from 10.10.2.5 to 10.10.1.5. Since the traffic is denied at the NIC level, the connection from VM2 to VM1 fails.
