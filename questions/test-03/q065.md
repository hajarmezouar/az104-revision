## Énoncé et corrigé fourni


You have a virtual network named VNET1 that includes the following subnets:
You also have the following Azure virtual machines with the listed network configurations:
For NSG1, you configure the following inbound security rule:
- Priority: 101
- Source: 10.10.2.0/24
- Destination: 10.10.1.0/24
- Destination port: TCP 1433
- Action: Allow
For NSG2, you configure the following inbound security rule:
- Priority: 125
- Source: 10.10.2.5
- Destination: 10.10.1.5
- Destination port: TCP 1433
- Action: Block
True or False:
`“VM1 can connect to the TCP port 1433 services on VM2.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer because there are no Network Security Groups (NSGs) applied to Subnet2, where VM2 resides, or directly to VM2's network interface. NSG1 is applied at Subnet1, allowing traffic from Subnet2 to Subnet1 on TCP port 1433. NSG2 is applied at VM1's network interface, but it explicitly blocks inbound traffic from 10.10.2.5 (VM2) to 10.10.1.5 (VM1) on TCP port 1433. However, the direction of traffic in this question is from VM1 to VM2, not the other way around. Therefore, the NSG rules blocking inbound traffic on VM1 do not apply in this scenario, and the outbound connection from VM1 to VM2 is not blocked.
