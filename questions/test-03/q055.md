## Énoncé et corrigé fourni


Your on-premises network hosts an Active Directory Domain Services (AD DS) domain named apexcore.com. The domain includes the following servers:
You are planning to migrate the apexcore.com domain to Azure.
You create an Azure virtual network named VNET1 with these configurations:
- Address space: 10.0.0.0/16
- Subnet configuration:
- Subnet name: Subnet1
- IPv4 address range: 10.0.1.0/24
You need to move DC1 into VNET1. The configuration must ensure that all member servers in apexcore.com can continue to resolve Active Directory DNS records correctly.
How should the Name resolution be configured?
Réponses:
**☑** Configure VNET1 to use a custom DNS server.
☐ Configure VNET1 to use the default Azure-provided DNS server.
☐ Create an Azure Private DNS zone named apexcore.com.
☐ Create an Azure public DNS zone named apexcore.com.
Explication
`Configure VNET1 to use a custom DNS server` is correct because to ensure that the member servers in apexcore.com can resolve Active Directory Domain Services (AD DS) DNS names, VNET1 should be configured to use the IP address of DC1 (acting as the DNS server) as a custom DNS server. This configuration will allow resources within VNET1 to resolve DNS queries for apexcore.com using DC1's DNS service, which is essential for Active Directory domain name resolution.
`Configure VNET1 to use the default Azure-provided DNS server` is incorrect because Azure’s default DNS server does not support resolving on-premises or custom domain names like apexcore.com.
`Create an Azure Private DNS zone named apexcore.com` is incorrect because, while a private DNS zone could theoretically support name resolution, it would not integrate seamlessly with AD DS DNS requirements. Using DC1 as the DNS server directly provides better compatibility with AD DS.
`Create an Azure public DNS zone named apexcore.com` is incorrect because a public DNS zone is intended for resolving internet-facing names and is not suitable for internal AD DS name resolution within VNET1.
