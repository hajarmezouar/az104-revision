You manage two Azure subscriptions named Subscription1 and Subscription2.
Subscription1 has the following virtual networks:
The virtual networks contain the following subnets:
Subscription 2 contains the following virtual network:
- Name: VNETA
- Address space: 10.10.128.0/17
- Location: Canada Central

True or False:
`“VNET1 and VNET2 can be peered.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer here. Azure virtual network peering supports connections between virtual networks under the following conditions:
- The address spaces of the VNets must not overlap
- The VNets can be in the same or different Azure regions
- The VNets can belong to the same or different subscriptions
In this case:
- VNET1 has an address space of `10.10.10.0/24`
- VNET2 has an address space of `172.16.0.0/16`
These address spaces do not overlap, which satisfies the IP requirement.
Additionally:
- VNET1 is located in West US
- VNET2 is located in West Europe
Azure supports global virtual network peering, which allows peering between virtual networks in different Azure regions.
Therefore, VNET1 and VNET2 can be peered using global VNet peering, and no technical limitation prevents this configuration.
Reference(s.):
- https://learn.microsoft.com/en-us/azure/virtual-network/virtual-network-peering-overview
- https://learn.microsoft.com/en-us/azure/virtual-network/virtual-network-manage-peering
