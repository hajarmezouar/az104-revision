## Énoncé et corrigé fourni


Your on-premises network hosts an Active Directory Domain Services (AD DS) domain named apexcore.com. The domain includes the following servers:
You are planning to migrate the apexcore.com domain to Azure.
You create an Azure virtual network named VNET1 with these configurations:
- Address space: 10.0.0.0/16
- Subnet configuration:
- Subnet name: Subnet1
- IPv4 address range: 10.0.1.0/24
You need to move DC1 into VNET1. The configuration must ensure that all member servers in apexcore.com can continue to resolve Active Directory DNS records correctly.
How should the IP address be configured?
Réponses:
**☑** Obtain an IP address automatically.
☐ Use 10.0.1.3
☐ Use 10.0.2.1
☐ Use 192.168.2.1
Explication
`Obtain an IP address automatically` is correct because, out of the options given, this is the most feasible solution. While it's generally best practice to assign a static IP to a Domain Controller (DC) to ensure consistent DNS resolution, obtaining an IP automatically can work as long as DC1 remains active. If DC1 is shut down, it may receive a different IP upon restart, which could disrupt DNS resolution.
`Use 10.0.1.3` is incorrect because the first four IP addresses within a subnet range (like 10.0.1.0/24) are reserved by Azure, making 10.0.1.3 unavailable for assignment.
`Use 10.0.2.1` is incorrect because, although it’s within the overall VNET1 address space, it falls outside of Subnet1’s range (10.0.1.0/24), which would prevent proper network connectivity.
`Use 192.168.2.1` is incorrect as this IP is part of the on-premises network and does not exist within VNET1’s address space, making it unusable in the Azure virtual network.
