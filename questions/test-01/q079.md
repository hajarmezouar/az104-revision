## Énoncé et corrigé fourni


You have an Azure subscription named Subscription1 that includes the following resources:
You assign a policy to RG6 as shown in the following table.
Additionally, the following action is performed:
- The tag RGroup: RG6 is applied directly to the resource group RG6.
After the policy assignment and tag configuration, you deploy a new virtual network named VNET2 into RG6.
Which tag(s) apply to VNET1?
Réponses:
☐ None
**☑** Department: D1 only
☐ Department: D1, and RGroup: RG6 only
☐ Department: D1, and Label: Value1 only
☐ Department: D1, RGroup: RG6, and Label: Value1
Explication
`Department: D1 only` is the correct answer here. According to the first table, VNET1 was already deployed in RG6 and has a tag of `Department: D1`. The Azure Policy that appends the `Label: Value1` tag was assigned after the deployment of VNET1 and therefore does not apply retroactively to existing resources. Azure policy with an `Append` effect only enforces the tagging requirement at the time of resource creation or modification, not on existing untouched resources.
The policy will apply to new resources deployed in RG6 after the policy was assigned. VNET1 is unaffected unless it is updated or redeployed.
`None` is incorrect because VNET1 already has a `Department: D1` tag.
`Department: D1, and RGroup: RG6 only` is incorrect because the `RGroup: RG6` tag was applied to the resource group (RG6), but tags from resource groups do not automatically inherit to the resources inside them unless explicitly applied via policy or ARM template.
`Department: D1, and Label: Value1 only` and `Department: D1, RGroup: RG6, and Label: Value1` are both incorrect because the `Label: Value1` tag would only apply to resources created after the policy was assigned.

- https://learn.microsoft.com/en-us/azure/governance/policy/concepts/effect-append
- https://learn.microsoft.com/en-us/azure/governance/policy/overview
