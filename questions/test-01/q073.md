## Énoncé et corrigé fourni


You have an Azure Storage account named storage1 that includes a blob container called container1. The default access tier for storage1 is set to Hot.
You configure lifecycle management rules for storage1 as summarized below:
You then carry out the following actions:
- October 1: Upload three files, Dep1File1.docx, File2.docx, and File3.docx, to container1.
- October 2: Edit Dep1File1.docx and File3.docx.
- October 5: Edit File2.docx.
True or False:
`“On October 10, you are able to read File2.docx without any delay.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer here. The blob File2.docx is stored in container1, but it does not match the prefix filter `container1/Dep1` defined in Rule1, so Rule1 does not apply to it. Only Rule2, which applies to all blobs in `storage1`, governs File2.docx.
Rule2 specifies that if base blobs are not modified for three days, they are moved to cool storage, and if not modified for nine days, they are moved to archive. File2.docx was last modified on October 5, and by October 10, only five days have passed since that modification. Therefore, it would have been moved to the cool tier, but not to the archive tier.
Blobs in the cool tier can be accessed without delay (unlike archive tier blobs that require rehydration). Hence, File2.docx can be read on October 10 without a delay.

- https://learn.microsoft.com/en-us/azure/storage/blobs/lifecycle-management-overview
