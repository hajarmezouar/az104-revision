## Énoncé et corrigé fourni


You have an Azure subscription that includes a Recovery Services vault named Vault1.
You plan to configure multi-user authorization (MAU) for Vault1.
Which Azure resource must be created before you can enable MAU?
Réponses:
☐ an Azure administrative unit
☐ an Azure managed identity
**☑** a resource guard
☐ a custom Azure role
Explication
a resource guard is correct because enabling Multi-User Authorization (MAU) in a Recovery Services vault requires creating a resource guard. A resource guard protects critical operations (such as disabling soft delete or stopping backup) by requiring additional authorization from designated approvers. The resource guard enforces MAU by ensuring operations cannot proceed without explicit approval from specified users or groups.
an Azure administrative unit is incorrect because administrative units are used for grouping Azure AD resources and delegating administrative tasks, not for securing critical Recovery Services vault operations.
an Azure managed identity is incorrect because managed identities are used to securely authenticate services with Azure resources, not for enabling or managing MAU in a Recovery Services vault.
a custom Azure role is incorrect because, while custom roles may provide granular permissions, they are not required to enable MAU. The primary requirement for MAU is the creation of a resource guard.
Reference(s):
- https://learn.microsoft.com/en-us/azure/storage/blobs/encryption-scope-manage?tabs=portal

## Analyse vérifiée

- **Statut :** réponse vérifiée ; la référence fournie dans le DOCX concerne Storage et ne justifie pas cette question.
- **Fait décisif :** l'autorisation multiutilisateur (MUA) protège les opérations critiques d'un coffre Recovery Services.
- **Pourquoi la réponse est correcte :** Azure Backup utilise une ressource **Resource Guard** comme autorisation supplémentaire. Il faut créer cette ressource puis l'associer au coffre.
- **Pourquoi les autres choix sont incorrects ici :** une unité administrative organise la délégation sur des objets Microsoft Entra ; une identité managée authentifie une charge de travail ; un rôle personnalisé règle des autorisations RBAC. Aucun ne remplace Resource Guard pour activer MUA.
- **Quand chaque autre choix serait correct :**
  - **Unité administrative :** « Je veux déléguer la gestion des utilisateurs d'un département dans Microsoft Entra. »
  - **Identité managée :** « Mon application Azure doit accéder à un autre service sans stocker de secret. »
  - **Rôle personnalisé :** « Les rôles Azure intégrés accordent plus de permissions que nécessaire pour mon équipe. »
- **Schéma ou tableau :** `Administrateur du coffre → opération critique → Resource Guard → contrôle des permissions → opération autorisée ou refusée`.
- **Règle à retenir :** MUA d'Azure Backup implique Resource Guard et une séparation des permissions sur le coffre et sur la garde.
- **Sources Microsoft Learn :** [Concept MUA](https://learn.microsoft.com/en-us/azure/backup/multi-user-authorization-concept) · [Créer Resource Guard et activer MUA](https://learn.microsoft.com/en-us/azure/backup/multi-user-authorization-tutorial).
