## Énoncé et corrigé fourni


You have an Azure subscription.
You create an Azure Resource Manager (ARM) template file named deploy.json. The template defines a StorageV2 storage account that uses a Premium_LRS SKU. The resource name is generated dynamically by combining an index value with a unique string, and the template uses a copy loop to deploy multiple instances of the storage account.
{
"$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
"contentVersion": "1.0.0.0",
"parameters": {
"location": {
"type": "string",
"defaultValue": "westus"
}
},
"resources": [
{
"apiVersion": "2019-04-01",
"type": "Microsoft.Storage/storageAccounts",
"name": "[concat(copyIndex(), 'storage', uniqueString(resourceGroup().id))]",
"location": "[resourceGroup().location]",
"sku": {
"name": "Premium_LRS"
},
"kind": "StorageV2",
"properties": {},
"copy": {
"name": "storagecopy",
"count": 3
}
}
]
}
You then connect to the subscription and run the following commands.
- New-AZResourceGroup -Name RG1 -Location “centralus”
- New-AZResourceGroupDeployment -ResourceGroupName RG1 -TemplateFile “deploy.json”
True or False:
`"The commands will create storage accounts in the West US Azure region."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because the storage accounts are created in the location of the resource group which is Central US.
NOTE: If the `location` value in the template uses:
- `[parameters('location')]`: the resource gets deployed to the location provided in the parameter (`westus` in this case).
- `[resourceGroup().location]`: the resource inherits the region from the resource group, regardless of the parameter.

- https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/copy-resources#resource-iteration
