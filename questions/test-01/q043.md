## Énoncé et corrigé fourni


An Azure subscription contains 10 virtual machines and the following resources:
You must ensure that Bastion1 can support 100 simultaneous SSH connections. The solution should require the least possible administrative effort.
What action should you take first?
Réponses:
☐ Configure scaling for the Bastion host.
**☑** Upgrade Bastion1 to the standard SKU.
☐ Create and associate a network security group (NSG).
☐ Resize the subnet of Bastion1.
Explication
`Upgrade Bastion1 to the standard SKU` is correct because with Basic SKU, only 2 instances can be created. And each instance supports upto 40 SSH concurrent users. Hence in order to support 10 sessions, we need to upgrade the SKU of the Bastion service to Standard which allows to define the number of instances you need. We need at least 3 instances in this case.
`Configure scaling for the Bastion host` is incorrect because this is only supported in Standard SKU of the Bastion service. Since the service is of type Basic, we first need to upgrade it to Standard.
`Create and associate a network security group (NSG)` is incorrect because an NSG only has rules for Inbound and Outbound traffic. It cannot help in configuring concurrent SSH sessions for Bastion service. For that you need to have multiple instances of the service running parallely,
`Resize the subnet of Bastion1` is incorrect because the size of the subnet does not matter here. For concurrent sessions, users can use the same machine to connect to backend VMs, so subnet does not need to have 100 IP addresses available.
