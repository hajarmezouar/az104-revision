## Énoncé et corrigé fourni


An Azure subscription contains an Azure Storage account named storageaccount1.
You export storageaccount1 as an Azure Resource Manager (ARM) template. The exported template defines the storage account type, location, SKU, encryption settings, access tier, and network access configuration. The network rules allow access by default and include a bypass for Azure services, with no virtual network rules or IP address restrictions specified.

True or False:
`"A server with the public IP address of 131.107.103.10 can access storageaccount1."`
Réponses:
**☑** True
☐ False
Explication
`True` is correct because default action is set to allow for Network ACLs. So any server on the public internet can access the storage account if it has the access keys.
A note about the `bypass` setting in the Network ACL:**
The `bypass` setting is used to allow trusted Azure services to access the storage account even when network rules restrict other traffic. For example, services like Azure Backup, Azure Site Recovery, or Azure Monitor often need access to storage accounts. When the `bypass` value includes `AzureServices`, these trusted services can bypass the firewall restrictions if the `defaultAction` is set to Deny.
In this case:
- The `defaultAction` is set to `Allow`, meaning all IPs (including public IPs) are currently allowed by default.
- The `bypass` setting is irrelevant in this situation because access isn’t restricted to begin with.
- If `defaultAction` were set to `Deny`, then the `bypass: AzureServices` would ensure that trusted Azure services can still reach the storage account — but not general users or applications, even if they are Azure-joined.
