## Énoncé et corrigé fourni


You have an Azure subscription and you create an Azure Resource Manager (ARM) template named Template.json.
The template defines the creation of a resource group called Marketing in the East US region and contains no parameters, variables, or outputs.
{
"$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
"contentVersion": "1.0.0.0",
"parameters": {},
"variables": {},
"resources": [
{
"type": "Microsoft.Resources/resourceGroups",
"apiVersion": "2024-11-01",
"location": "eastus",
"name": "Marketing"
}
],
"outputs": {}
}You now want to deploy Template.json by using Azure Cloud Shell.
Which PowerShell cmdlet should you use to perform this deployment?
Réponses:
**☑** New-AzSubscriptionDeployment
☐ New-AzManagementGroupDeployment
☐ New-AzResourceGroupDeployment
☐ New-AzTenantDeployment
Explication
`New-AzSubscriptionDeployment` is the correct answer here. The ARM template defines a resource group creation, but it's not scoped to an existing resource group because it creates the group itself. Therefore, it must be deployed at the subscription level, not the resource group level. The `New-AzSubscriptionDeployment` cmdlet is specifically used to deploy templates that create or manage resource groups.
`New-AzResourceGroupDeployment` is incorrect because this cmdlet is used when deploying resources within a specific, existing resource group. Since the template creates a new resource group (`"type": "Microsoft.Resources/resourceGroups"`), this cmdlet cannot be used—it assumes the resource group already exists.
`New-AzManagementGroupDeployment` is incorrect because it is used for ARM deployments at the management group level, which is not applicable here. The template is not managing resources across management groups.
`New-AzTenantDeployment` is incorrect because it is used to deploy tenant-scoped resources (such as Microsoft Entra tenants or policy definitions at the tenant level). That does not apply in this scenario.
