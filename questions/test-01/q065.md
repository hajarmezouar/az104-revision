## Énoncé et corrigé fourni


You have an Azure subscription with the following virtual networks:
The subnets are configured with the following IP address ranges:
- Subnet1: 10.1.128.0/24
- Subnet21: 192.168.0.0/17
- Subnet22: 192.168.128.0/17
- Subnet3: 172.16.1.0/24
You plan to deploy a container app named app1 in the East US region.
To support this, you need to create a container app environment named env1 with the following conditions:
- Uses its own (and existing) virtual network.
- Uses its own (and new) subnet.
- Is connected to the smallest possible subnet.
To which virtual networks can you connect env1?
Réponses:
☐ VNet1 only
☐ VNet2 only
**☑** VNet3 only
☐ VNet1 or VNet2 only
☐ VNet2 or VNet3 only
☐ VNet1, VNet2, or VNet3
Explication
`VNet3 only` is correct because the requirement specifies that the container app environment (env1) must use its own (and new) subnet and must connect to the smallest possible subnet. Additionally, the subnet must be able to accommodate a minimum /23 CIDR range, which requires at least 512 IP addresses.
- VNet1 has an IP address space of /23 (512 IP addresses in total). Subnet1 already occupies /24, which uses 256 addresses, leaving insufficient IP addresses to create a new /23 subnet.
- VNet2 has an IP address space of /16 (65,536 IP addresses). However, it already contains two subnets, each with /17 ranges (32,768 IP addresses each). This allocation exhausts the available IP space, leaving no room for an additional /23 subnet.
- VNet3 also has an IP address space of /16 (65,536 IP addresses). Subnet3, which occupies /24, only consumes 256 addresses, leaving sufficient IP space to create a new /23 subnet.
