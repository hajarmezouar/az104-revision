## Énoncé et corrigé fourni


You have a Microsoft Entra tenant named ironclad.onmicrosoft.com, and a user named Admin1 is assigned the User administrator role. An external partner uses a Microsoft account with the sign-in address user1@outlook.com.
When Admin1 tries to invite this external partner to access the Microsoft Entra tenant, the invitation fails with the error message:
`“Unable to invite user user1@outlook.com - Generic authorization exception”.`
You need to make sure that Admin1 is able to successfully invite the external partner to sign in to the Microsoft Entra tenant.
What action should you take?
Réponses:
☐ From the Custom domain names blade, add a custom domain.
**☑** From the Users blade, modify the External collaboration settings.
☐ From the Organizational relationships blade, add an identity provider.
☐ From the Roles and administrators blade, assign the Security administrator role to Admin1.
Explication
`From the Users blade, modify the External collaboration settings` is the correct answer here. The error message “Generic authorization exception” typically occurs when external collaboration is not properly configured to allow guest invitations. In Microsoft Entra ID (formerly Azure AD), external user invitations depend on the External collaboration settings under the Users blade. By enabling guest invites and configuring who can invite external users (like Admin1), you can resolve this error and allow Admin1 to successfully invite the partner user.
`From the Custom domain names blade, add a custom domain` is incorrect because adding a custom domain is unrelated to external collaboration or guest user invitations. It's used for domain branding and user email domains within the tenant.
`From the Organizational relationships blade, add an identity provider` is incorrect because this is typically used for B2B direct connect or federation with another organization, not for inviting an individual Microsoft account user like `user1@outlook.com`.
`From the Roles and administrators blade, assign the Security administrator role to Admin1` is incorrect because the User administrator role already grants the ability to invite guest users—if external collaboration is enabled. The issue isn’t with permissions but with the tenant-wide settings for guest collaboration.
