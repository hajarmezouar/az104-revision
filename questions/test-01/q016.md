## Énoncé et corrigé fourni


An Azure environment contains the following virtual machines:
- VM1: IP address 10.0.0.4, deployed in VNET1
- VM2: IP address 172.16.0.4, deployed in VNET2
- VM3: IP address 192.168.0.4, deployed in VNET3
- VM4: IP address 192.168.0.5, deployed in VNET3
The virtual networks VNET1, VNET2, and VNET3 are peered with each other.
A DNS server is running on VM4. This DNS server is authoritative for the contoso.com zone and contains the following records:
- Server1: "A" record with the value 131.107.2.3
- Server2: "A" record with the value 131.107.2.4
Additionally, VNET1 and VNET2 are linked to an Azure private DNS zone named contoso.com, which contains these records:
- Server1: "A" record with the value 131.107.3.3
- Server2: "A" record with the value 131.107.3.4
The virtual networks are configured to use the following DNS servers:
- VNET1: Azure-provided default DNS
- VNET2: Custom DNS server at 192.168.0.5
- VNET3: Custom DNS server at 192.168.0.5
True or False:
`"From VM2, server1.contoso.com resolves to 131.107.3.3."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because VM2 is connected to private DNS zone, but the VNet itself is connected to a custom DNS server where we do see that an A record exists for Server1 which will resolve from server1.contoso.com to 131.107.2.3.
The key point here is that DNS resolution for a VM depends on the DNS server settings configured at the VNet level, not just the private DNS zone links.
- VM2 is in VNET2, and according to the table, VNET2 is configured to use a custom DNS server (192.168.0.5). That IP address belongs to VM4, which is itself authoritative for the `contoso.com` DNS zone (see the table showing Server1 → 131.107.2.3 and Server2 → 131.107.2.4).
- Even though VNET2 is also linked to the Azure private DNS zone `contoso.com` (which contains Server1 → 131.107.3.3 and Server2 → 131.107.3.4), that zone will not be queried by VMs in VNET2. Why? Because Azure Private DNS only applies if the VNet is configured to use the Azure-provided DNS. Since VNET2 is overridden to use the custom DNS server, all queries (like `server1.contoso.com`) go to VM4’s DNS instead.
- Therefore, when VM2 resolves `server1.contoso.com`, it will get the record from VM4’s DNS server (131.107.2.3), not from the private DNS zone (131.107.3.3).

- https://learn.microsoft.com/en-us/azure/dns/private-dns-virtual-network-links
