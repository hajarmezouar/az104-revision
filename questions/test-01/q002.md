## Énoncé et corrigé fourni


You have an Azure subscription that includes the following public IP address resources:
- IP1 – IPv4, Standard SKU, Regional tier, Static assignment
- IP2 – IPv4, Standard SKU, Global tier, Static assignment
- IP3 – IPv4, Basic SKU, Regional tier, Dynamic assignment
- IP4 – IPv4, Basic SKU, Regional tier, Static assignment
- IP5 – IPv6, Standard SKU, Regional tier, Static assignment
You plan to deploy an Azure Firewall Premium instance named FW1.
Which of these public IP addresses are eligible to be associated with FW1?
Réponses:
**☑** IP1 only
☐ IP1 and IP2 only
☐ IP1, IP2, and IP5 only
☐ IP1, IP2, IP4, and IP5 only
Explication
IP1 is correct because it is an IPv4, Standard SKU, Regional tier, Static public IP address. Azure Firewall supports Standard SKU public IP addresses, and Azure Firewall requires a static IPv4 public IP configuration.
IP2 is incorrect because, although it is an IPv4 Standard SKU address with Static assignment, it uses the Global tier. Global-tier public IP addresses are intended for the frontends of cross-region Azure Load Balancers. Azure Firewall is a regional resource and its public IP must therefore use the Regional tier.
IP3 is incorrect because it uses the Basic SKU and Dynamic assignment. Azure Firewall supports Standard SKU public IP addresses; Basic SKU public IP addresses aren't supported. Additionally, Azure Firewall uses static rather than dynamic public IPv4 addresses.
IP4 is incorrect because, although it is an IPv4 Regional address with Static assignment, it uses the Basic SKU. Azure Firewall does not support Basic SKU public IP addresses.
IP5 is incorrect because it is an IPv6 public IP address. Azure Firewall currently does not support IPv6; it operates using IPv4, even when deployed in a dual-stack virtual network.
Therefore, among the listed public IP addresses, only IP1 satisfies all the requirements for association with FW1: IPv4, Standard SKU, Regional tier, and Static assignment.
