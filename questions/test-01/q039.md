## Énoncé et corrigé fourni


You manage a Microsoft Entra tenant.
You need to modify the Default user role permissions to meet the following requirements:
- Standard users must not be able to create new service principals.
- Standard users must be limited to using PowerShell or Microsoft Graph when managing their own Azure resources.
The current Default user role permissions settings are configured as follows:
User permissions
- `Setting 1`: Users can register applications: Yes
- `Setting 2`: Restrict non-admin users from creating tenants: No
- `Setting 3`: Users can create security groups: Yes
Guest user access
- `Setting 4`:Guest user access restrictions: Guest users have limited access to properties and memberships of directory objects
Administration center
- `Setting 5`: Restrict access to Microsoft Entra admin center: No
Session settings
- `Setting 6`: Show keep user signed in: Yes
Based on the requirements and the current configuration, which two settings should you modify?
Réponses (plusieurs réponses possibles)
**☑** 1
☐ 2
☐ 3
☐ 4
**☑** 5
☐ 6
Explication
`1` is correct because this setting enables the users to register an application in Microsoft Entra from which a service principal can be created. So in order to prevent this, this setting needs to be turned off.
`5` is correct because this setting, if turned on, will not allow non-admin users to access Microsoft Entra admin portal, and hence not allow them to manage their resources from it. So the only way those users can manage their resources are via Powershell, CLI or Microsoft graph API (for Microsoft Entra objects).
