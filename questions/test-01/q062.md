Explication
`4` is correct. The App Service Plan starts with 1 instance. When the CPU usage is consistently at 90% for 1 hour, the scale-out rule applies. The rule checks if the maximum CPU percentage exceeds 85% over a 5-minute window, and if it does, it increases the instance count by 1. After scaling out, a 5-minute cooldown period begins before the next evaluation.
Since both the evaluation period and the cooldown duration are set to 5 minutes, the system can scale out every 5 minutes as long as the CPU remains above 85%. Therefore, in 60 minutes, scaling can occur up to 12 times. However, the maximum instance limit is capped at 5, so only 4 scale-out operations can occur before hitting the cap, bringing the instance count from 1 to 5.
Afterward, when the CPU usage drops below 30% and stays there for 9 minutes, the scale-in rule (which evaluates on a 5-minute basis and then applies a 5-minute cooldown) is triggered. Only 1 full scale-in cycle can be completed during that 9-minute low usage period. So, the instance count is reduced by 1, resulting in a final count of 4 instances.
