## Énoncé et corrigé fourni


You have an Azure Storage account named contoso2024 that contains the following resources:
- container1: a blob container that stores File1
- share1: an Azure File share that stores File2
You have the following users and permissions assigned for contoso2024:
- User1: Reader role
- User2: Storage Account Contributor role
- User3: Has an access key for contoso2024
The storage account contoso2024 is configured with secure transfer enabled, public blob access enabled, storage account key access disabled, and Azure Active Directory authorization disabled in the Azure portal.
True or False:
`"User1 can read File1."`
Réponses:
☐ True
**☑** False
Explication
`False` is correct because Reader role gives you access to read the metadata and configuration of the storage account (on the service-level). It does not give you read access to the content of blob storage. Hence User1 cannot read File1.
Note: While "Allow Blob public access" is enabled at the storage account level, this only means that public access is permitted if the individual container is configured to allow it (such as "container" or "blob" level anonymous access). However, unless the container is explicitly set to public access (which is not indicated in the question), anonymous users cannot access the blob data. In this scenario, User1 has only the Reader role (control plane access) and no data plane permissions, and we have no information that public access is configured on the container. Therefore, User1 cannot read File1.

- https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage?tabs=azure-portal
