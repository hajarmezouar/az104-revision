## Énoncé et corrigé fourni


An Azure subscription contains a storage account named contoso2024. The storage account includes the following resources:
- cont1: Blob container
- share1: File share
The contoso2024 storage account is configured with the settings shown below. The configuration defines the account kind, performance tier, security and access options, minimum TLS version, copy scope, and the default blob access tier.
You also have a Microsoft Entra tenant with the following users, each assigned a Shared Access Signature (SAS) token for contoso2024:
True or False:
`"User1 can access content in cont1."`
Réponses:
**☑** True
☐ False
Explication
`True` is correct because User1 has a User Delegation SAS, which does not rely on the storage account keys. In this storage account, the setting Allow storage account key access is disabled, meaning that any SAS signed with the account keys (such as an Account SAS or a Service SAS) cannot be used. However, a User Delegation SAS is signed with a user delegation key that is derived from the user’s Microsoft Entra ID credentials, not from the storage account keys. This makes it valid and usable even when key access is disabled.
The Secure transfer required setting enforces that all connections must use HTTPS, but it is not the determining factor in this scenario because a User Delegation SAS already generates HTTPS URLs by default. Therefore, the reason User1 can access content in cont1 is specifically due to the use of a User Delegation SAS, which remains supported under the current configuration.
