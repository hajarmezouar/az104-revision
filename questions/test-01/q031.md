## Énoncé et corrigé fourni


You have multiple Azure virtual machines deployed in a virtual network named VNet1.
You configure an Azure Storage account as shown below. The networking settings restrict public network access to selected virtual networks and subnets, and VNet1 is explicitly added with a service endpoint enabled on a specific subnet. No additional IP address ranges are configured in the firewall section. The network routing preference is set to use Microsoft network routing, and no private endpoints are configured.
Based on the configuration shown, select the option that correctly completes the following statement:
`"The virtual machines on the 10.2.9.0/24 subnet will have network connectivity to the file shares in the storage account ________________________________."`
Réponses:
☐ always
☐ during a backup
**☑** never
Explication
`Never` is correct.
Public network access is set to "Enabled from selected virtual networks and IP addresses." This means that the storage account can only be accessed from specific virtual networks and IP addresses.
Under Virtual networks, VNet1 is listed with a subnet named Prod (10.2.0.0/24) having an "Enabled" endpoint status. This means the storage account permits access only from this specific subnet within VNet1.
The address space of VNet1 is 10.2.0.0/16, but the only associated subnet is 10.2.0.0/24, which includes IP addresses in the range 10.2.0.0 to 10.2.0.255.
The virtual machines on the 10.2.9.0/24 subnet would have IP addresses in the range 10.2.9.0 to 10.2.9.255. This range is outside the defined Prod subnet (10.2.0.0/24).
Since the network connectivity to the storage account is segmented by subnets and not by the entire virtual network, the virtual machines on the 10.2.9.0/24 subnet will not have network connectivity to the file shares in the storage account.
Therefore, the virtual machines on the 10.2.9.0/24 subnet will never have network connectivity to the file shares in the storage account.
