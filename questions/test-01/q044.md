## Énoncé et corrigé fourni


You have an Azure App Service app named App1 that is currently running two instances.
You configure an autoscale rule as shown below. The rule monitors the Memory Percentage metric across all instances, evaluates the average memory usage at a one-minute time grain, and triggers a scale-out action when the defined threshold is exceeded for a specified duration. When the condition is met, the rule increases the instance count by one and applies a cooldown period before another scale action can occur.
For the Instance limits scale condition, the Maximum number of instances is set to 5.
Over a continuous 30-minute period, App1 uses 80 percent of the available memory.
What is the maximum number of instances that App1 can reach during the 30-minute period?
Réponses:
☐ 2
☐ 3
☐ 4
**☑** 5
Explication
`5` is correct because it starts with 2 instances. After the first 15 min, it increases the count by 1 instance. The new count is 3 after 15 minutes. 5 minutes is the cool down period in which no scaling happens. After these 5 minutes, at 20 minutes past the starting point, the scaling happens again since the Memory percentage is still more than 70%. Similarly after 25 min, there will be one more increase in the instance count. Total count at this point is 5. So after the next 5 minutes (making it 30 minutes), it cannot increase the count anymore because the max instance count is set to 5. So the final count will remain 5 after 30 minutes.
