## Énoncé et corrigé fourni


You have an Azure Storage account named storage1 that includes a blob container called container1. The default access tier for storage1 is set to Hot.
You configure lifecycle management rules for storage1 as summarized below:
You then carry out the following actions:
- October 1: Upload three files, Dep1File1.docx, File2.docx, and File3.docx, to container1.
- October 2: Edit Dep1File1.docx and File3.docx.
- October 5: Edit File2.docx.
True or False:
`“On October 10, you are able to read File3.docx without any delay.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer here. File3.docx is stored in container1 and does not fall under the prefix filter `container1/Dep1` used in Rule1. Therefore, only Rule2 applies to this file.
Rule2 states that if a base blob is not modified for three days, it moves to cool storage, and after nine days of no modification, it moves to archive storage. File3.docx was last modified on October 2, and by October 10, it has not been modified for eight days.
This means File3.docx would have been moved to cool storage on October 5, but it would not yet be in the archive tier (which would happen on October 11). Since the cool access tier allows immediate read access without delay, File3.docx is readable on October 10 without requiring rehydration.

- https://learn.microsoft.com/en-us/azure/storage/blobs/lifecycle-management-overview
