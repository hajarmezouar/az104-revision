## Énoncé et corrigé fourni


An Azure subscription contains a user named User1 along with the following resources:
- RG1, which is a resource group
- networkinterface1, which is a virtual network interface
- NSG1, which is a network security group
The network security group NSG1 is linked to networkinterface1.
User1 has been assigned the following roles related to NSG1:
- Contributor at the NSG1 resource scope
- Reader at the subscription scope (inherited)
- Storage Account Contributor at the resource group scope (inherited)
True of False:**
`"User1 is able to create a storage account within RG1."`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer because even though the question states that User1 has role assignments on NSG1, the Storage Account Contributor role is assigned at the Resource Group (RG1) level, as shown in the role assignments table. This means User1 inherits the permissions provided by that role for all resources within RG1.
The `Storage Account Contributor` role allows full management of storage accounts, including the ability to create them. Since this role is applied at the RG1 scope, User1 can create storage accounts anywhere within that resource group regardless of their other roles at narrower scopes like NSG1.
The mention of role assignments for NSG1 in the question context simply lists additional roles that User1 has, but those do not restrict or override the broader permissions granted at the resource group level. RBAC in Azure is additive by design, meaning User1’s permissions accumulate across scopes.
