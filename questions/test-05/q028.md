## Énoncé et corrigé fourni


Note: This question is part of a set of related questions that use the same scenario. Each question proposes a different solution that may or may not satisfy the stated requirement.
You manage an Azure virtual machine named ProdVM01, which was deployed using a custom Azure Resource Manager template called deployVM.json.
You receive an alert stating that ProdVM01 will be affected by a scheduled platform maintenance event.
You must immediately relocate ProdVM01 to another host to avoid the upcoming maintenance impact.
Proposed solution: `Move ProdVM01 to another resource group from the RG blade.`
Does this solution meet the requirement?
Réponses:
☐ Yes
**☑** No
Explication
`No` is the correct answer here. Moving ProdVM01 to another resource group from the resource group blade is a logical metadata move within Azure Resource Manager. It does not involve changing the physical host on which the virtual machine runs. The VM’s underlying infrastructure—including the compute host—remains the same.
Since the goal is to move ProdVM01 to a different host immediately (to avoid disruption due to planned maintenance), this solution does not meet the requirement. The correct action would be to redeploy the virtual machine using the Redeploy option, which moves the VM to a new physical host.
Reference(s.):
- https://learn.microsoft.com/en-us/troubleshoot/azure/virtual-machines/windows/redeploy-to-new-node-windows
