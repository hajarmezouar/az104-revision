## Énoncé et corrigé fourni


You have two Azure virtual machines as shown in the following table. Each virtual machine runs a different operating system, has both private and public IP addresses assigned, and is connected to the same virtual network. One virtual machine has a DNS suffix configured in the operating system, while the other does not.
You then create the following Azure DNS resources:
- A public DNS zone named contoso.com
- A private DNS zone named fabrikam.com
You perform the following actions:
- For fabrikam.com, you create a virtual network link to vnet1 and enable automatic registration.
- For contoso.com, you assign the Owner role to both vm1 and vm2.
True of False:
“The DNS A record for vm2 is created in fabrikam.com and resolves to the IP address 10.0.1.5.”
Réponses:
**☑** True
☐ False
Explication
`True` is correct because fabrikam.com is an Azure Private DNS zone that is linked to vnet1 with automatic registration enabled. When automatic registration is enabled, Azure automatically creates DNS A records for all virtual machines connected to the linked virtual network.
vm2 is connected to vnet1 and has a private IP address of 10.0.1.5, so Azure automatically registers an A record for vm2.fabrikam.com that resolves to the private IP address.
The operating system type of vm2 and the absence of a DNS suffix configured inside the operating system do not affect Azure Private DNS auto-registration, as the registration is handled by the Azure platform.
The public DNS zone contoso.com and the assignment of the Owner role to the virtual machines are not relevant to Private DNS auto-registration and do not influence the creation of records in the fabrikam.com private DNS zone.
Reference(s):
- https://learn.microsoft.com/en-us/azure/dns/private-dns-autoregistration
