## Énoncé et corrigé fourni


You have an Azure subscription named Subscription1 and an on-premises deployment of Microsoft System Center Service Manager.
Within Subscription1, there is a virtual machine named VM1.
You must ensure that Service Manager generates an alert whenever the available memory on VM1 drops below 10 percent.
What should you do first?
Réponses:
☐ Create an automation runbook
☐ Deploy a function app
**☑** Deploy the IT Service Management Connector (ITSM)
☐ Create a notification
Explication
`Deploy the IT Service Management Connector (ITSM)` is the correct answer here. The IT Service Management Connector (ITSM) allows you to integrate Azure Monitor with IT service management tools such as System Center Service Manager (SCSM). This connector enables alerts from Azure (e.g., when VM1's available memory drops below a threshold) to automatically generate incidents or alerts within Service Manager.
Before you can generate alerts or trigger incidents in Service Manager based on Azure metrics, you must first deploy and configure the ITSM connector in Azure. Only then can you map Azure alerts (like memory thresholds) to corresponding actions in Service Manager.
`Create an automation runbook` is incorrect because automation runbooks are used for remediating or performing actions based on alerts, not for integrating with Service Manager directly.
`Deploy a function app` is incorrect as it’s generally used for executing custom serverless logic—not necessary in this scenario where a built-in integration exists via ITSM Connector.
`Create a notification` is incorrect because notifications are used to inform users via email or SMS, but not to trigger actions or alerts in Service Manager.
