## Énoncé et corrigé fourni


You have an Azure subscription named Sub1 that contains two users named User1 and User2.
You must assign Azure role-based access control (RBAC) roles to both users so they can perform the following actions within Sub1:
- User1 must view the data in any storage account.
- User2 must assign users the Contributor role for storage accounts.
The assignment must follow the principle of least privilege.
Which RBAC role should you assign to User 1?
Réponses:
☐ Owner
☐ Contributor
**☑** Reader and Data Access
☐ Storage Account Contributor
☐ User Access Administrator
Explication
`Reader and Data Access` is the correct role to assign to User1. This role provides read-only access to management operations (like the standard Reader role), but also adds the ability to read the data inside Azure Storage containers and blobs, queues, tables, and files. This aligns perfectly with the requirement that User1 must be able to view the data in any storage account, without allowing write or management capabilities. It also adheres to the principle of least privilege, as it grants exactly what is required and nothing more.
`Owner` is incorrect because it grants full access to manage all resources, including access management permissions. This is far more than what User1 needs just to view storage data, and violates the principle of least privilege.
`Contributor` is incorrect because while it allows full management of resources, it does not grant access to the underlying data in storage accounts (like reading blob contents). So it’s not sufficient for User1's data access requirement, and it overgrants permissions on the management plane.
`Storage Account Contributor` is incorrect because it provides management access to storage accounts (e.g., configuring settings, managing firewalls), but it does not grant data plane access (like reading blobs or files). Therefore, this role does not meet User1’s requirement to view the data inside storage accounts.
`User Access Administrator` is incorrect because it allows managing role assignments, not accessing data. This role is relevant for User2’s requirement, but not for User1. It provides no data access or management access to storage resources, so it is not applicable here.
