## Énoncé et corrigé fourni


Note: This question is part of a set of related questions that use the same scenario. Each question proposes a different solution that may or may not satisfy the stated requirement.
You manage an Azure virtual machine named ProdVM01, which was deployed using a custom Azure Resource Manager template called deployVM.json.
You receive an alert stating that ProdVM01 will be affected by a scheduled platform maintenance event.
You must immediately relocate ProdVM01 to another host to avoid the upcoming maintenance impact.
Proposed solution: `From the Updates blade, you click Enable.`
Does this solution meet the requirement?
Réponses:
☐ Yes
**☑** No
Explication
`No` is the correct answer here. Clicking Enable from the Updates blade typically refers to enabling automatic VM guest patching or maintenance control features, depending on the context. However, this action does not immediately move the VM to a different host.
The goal is to move ProdVM01 to a different physical host immediately to avoid potential impact from scheduled maintenance. The correct action to achieve that is to use the Redeploy option, which reprovisions the virtual machine onto a new physical host in the same region.
Reference(s.):
- https://learn.microsoft.com/en-us/troubleshoot/azure/virtual-machines/windows/redeploy-to-new-node-windows
