## Énoncé et corrigé fourni


You have an Azure subscription that contains the following virtual machines, all deployed in the same virtual network (VNET1):
- VM-A
- OS: Windows Server
- Subnet: SubnetA
- VM-B
- OS: Windows Server
- Subnet: SubnetB
- VM-C
- OS: Red Hat Enterprise Linux
- Subnet: SubnetC
Each virtual machine’s network interface is configured with the following DNS settings:
- VM-A -> No DNS server configured
- VM-B -> 192.168.10.15
- VM-C -> 192.168.10.15
At the virtual network level, custom DNS settings are configured with the following DNS server:
- 193.77.134.10
All virtual machines can successfully reach both DNS servers (192.168.10.15 and 193.77.134.10).
True or False:
`“VM-C connects to 192.168.10.15 for DNS queries."`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer because VM-C is explicitly configured with the DNS server 192.168.10.15 on its network interface.
In Azure, when a virtual machine’s NIC is manually configured with a DNS server IP, it overrides the DNS server settings configured at the virtual network level. As a result, VM-C will use 192.168.10.15 for all DNS queries unless that server is unreachable and multiple DNS servers are configured on the NIC (which is not shown in this case).
Therefore, VM-C connects to 192.168.10.15 for DNS resolution.
