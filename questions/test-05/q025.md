## Énoncé et corrigé fourni


Note: This question is part of a set of related questions that use the same scenario. Each question proposes a different solution that may or may not satisfy the stated requirement.
You manage an Azure virtual machine named ProdVM01, which was deployed using a custom Azure Resource Manager template called deployVM.json.
You receive an alert stating that ProdVM01 will be affected by a scheduled platform maintenance event.
You must immediately relocate ProdVM01 to another host to avoid the upcoming maintenance impact.
Proposed solution: `Move the VM to a different resource group from the Overview balde.`
Does this solution meet the requirement?
Réponses:
☐ Yes
**☑** No
Explication
`No` is the correct answer here. Moving a virtual machine to a different resource group does not change the physical host on which the VM is running. The operation is a metadata-level move within Azure Resource Manager, and the underlying compute resources (including the physical host) remain unchanged.
Since the goal is to move ProdVM01 to a different host immediately (e.g., to avoid upcoming planned maintenance), simply moving the VM to a different resource group does not meet the requirement.
To move a VM to a different host, you must perform an operation that redeploys the VM, such as using the Redeploy option from the Azure portal or running the `az vm redeploy` command. This action will provision the VM on a new physical host.
Reference(s.):
- https://learn.microsoft.com/en-us/troubleshoot/azure/virtual-machines/windows/redeploy-to-new-node-windows
