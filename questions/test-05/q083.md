## Énoncé et corrigé fourni


You have an Azure subscription that contains the following virtual machines, all deployed in the same virtual network (VNET1):
- VM-A
- OS: Windows Server
- Subnet: SubnetA
- VM-B
- OS: Windows Server
- Subnet: SubnetB
- VM-C
- OS: Red Hat Enterprise Linux
- Subnet: SubnetC
Each virtual machine’s network interface is configured with the following DNS settings:
- VM-A -> No DNS server configured
- VM-B -> 192.168.10.15
- VM-C -> 192.168.10.15
At the virtual network level, custom DNS settings are configured with the following DNS server:
- 193.77.134.10
All virtual machines can successfully reach both DNS servers (192.168.10.15 and 193.77.134.10).
True or False:
`“VM-A connects to 193.77.134.10 for DNS queries.”`
Réponses:
**☑** True
☐ False
Explication
`True` is correct because VM-A does not have a custom DNS server configured at the network interface level. In such cases, Azure virtual machines inherit their DNS server settings from the virtual network (VNET) they are connected to. From the information provided, VNET1 is configured with a single custom DNS server: 193.77.134.10. Therefore, VM-A uses 193.77.134.10 for DNS queries. The DNS server 192.168.10.15 is manually configured only for VM-B and VM-C at their respective NIC level and is not part of the VNET-wide configuration. Since VM-A lacks its own DNS override, it relies solely on the VNET1 configuration.
