## Énoncé et corrigé fourni


You have an Azure subscription that contains the following virtual machines, all deployed in the same virtual network (VNET1):
- VM-A
- OS: Windows Server
- Subnet: SubnetA
- VM-B
- OS: Windows Server
- Subnet: SubnetB
- VM-C
- OS: Red Hat Enterprise Linux
- Subnet: SubnetC
Each virtual machine’s network interface is configured with the following DNS settings:
- VM-A -> No DNS server configured
- VM-B -> 192.168.10.15
- VM-C -> 192.168.10.15
At the virtual network level, custom DNS settings are configured with the following DNS server:
- 193.77.134.10
All virtual machines can successfully reach both DNS servers (192.168.10.15 and 193.77.134.10).
True or False:
`“VM-B connects to 193.77.134.10 for DNS queries”`
Réponses:
☐ True
**☑** False
Explication
`False` is the correct answer because VM-B is explicitly configured with a custom DNS server: 192.168.10.15 on its network interface.
When a virtual machine has a DNS server manually set at the NIC level, this custom setting overrides the DNS settings inherited from the virtual network (VNET1).
As a result, VM-B will only use 192.168.10.15 for DNS resolution, and it will not use the secondary DNS server (193.77.134.10) defined at the VNET level unless 193.77.134.10 is manually added as a secondary DNS server on the NIC itself.

- https://learn.microsoft.com/en-us/azure/virtual-network/virtual-networks-faq#can-i-specify-a-custom-dns-server
- https://learn.microsoft.com/en-us/azure/dns/dns-overview
