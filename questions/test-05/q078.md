## Énoncé et corrigé fourni


Note: This question is part of a set of related questions that use the same scenario. Each question proposes a different solution that may or may not satisfy the stated requirement.
You have three Azure subscriptions named Sub1, Sub2, and Sub3, all associated with a single Microsoft Entra tenant.
The tenant includes a user named User1, a security group named Group1, and a management group named MG1. User1 is a member of Group1.
Both Sub1 and Sub2 are assigned to MG1.
Sub1 contains a resource group named RG1, and RG1 hosts five Azure Functions.
The following role assignments are configured at the MG1 scope:
- Group1 is assigned the Reader role
- User1 is assigned the User Access Administrator role
Additionally:
- User1 is assigned the Virtual Machine Contributor role on Sub1 and Sub2
- User1 is assigned the Contributor role on RG1
True or False:
`“Members of Group1 can view the configuration settings of the Azure Functions.”`
Réponses:
**☑** True
☐ False
Explication
`True` is the correct answer here. The members of Group1 can view the configurations of the Azure functions because Group1 has been assigned the Reader role at the management group level (MG1). Since Sub1 and Sub2 are members of MG1, and RG1 (which contains the Azure Functions) is part of Sub1, the Reader role cascades down from MG1 to Sub1 and RG1.
The Reader role allows users to view all resources, including their configurations, but does not permit any modifications. Therefore, even without direct permissions at the resource group or subscription level, Group1 members inherit read-only access and can view the Azure Functions in RG1.
Reference(s.):
- https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles#reader
- https://learn.microsoft.com/en-us/azure/governance/management-groups/overview
